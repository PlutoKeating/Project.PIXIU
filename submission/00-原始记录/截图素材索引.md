## 演示数据与复现操作

只使用明确标注的公开合成数据，不复用或清空用户真实记忆、同步身份及会话历史。
每组操作记录输入、所选范围、设备角色和预期结果；保存的合成记忆只能在明确限定
自己的目标后清理。模型输出不得被预先注入、替换或用后台写库伪装成界面操作。

1. 核验最终候选安装包及来源提交，在真实麒麟 V11 桌面完成安装并记录结果。
2. 通过命令和应用菜单进入同一宿主，确认实际运行二进制与包一致。
3. 在 Agent 和管理页完成同范围写入、检索、更新和证据查看，保留真实状态。
4. 用已验证的实现逐项完成表中管理、设备、隐私、主题及升级场景，再采集对应画面。
5. 核对每张图的内容、敏感信息、布局与状态，生成摘要并更新清单、画廊及引用文档。

## 画面布局、使用边界与未覆盖项

安装与启动三张须保持用户要求的操作内容、相对窗口布局和画面状态。
终端安装图使用真实终端区域；命令启动图保留终端背景与前景主窗口；菜单启动图
保留应用菜单与主窗口同屏。逐项核对实际分辨率、窗口坐标、尺寸、焦点和菜单状态，
不能以“操作语义相同”代替完全一致的布局验收。

不得通过拉伸、重绘、拼接、隐藏错误或替换文字伪造画面。截图中的系统水印、警告
与权限状态如实保留；涉及敏感信息时应在采集前使用不含敏感内容的真实操作场景。
PPT 或手册内使用局部图片时，明确标注局部展示并保留对应正式实拍原图。

所有上表场景目前均待新实拍验收，尤其多设备、人工遗忘确认、升级回滚、缩放、
键盘焦点、长文本、错误和停止状态。不得把旧截图、构建成功、接口单测或模型答案
当作这些场景已经完成的证据。

## 采集工具与文件校验

仓库工具 `backend/scripts/capture_desktop.py` 向运行中的 libvirt 桌面发送真实输入，
通过 `virsh screenshot` 采集真实帧，不生成软件界面。宿主需要 Python 3 与 virsh；
来宾区域采集需要 SSH/ImageMagick，X11 文本粘贴需要 GTK 3 Python 绑定。
这些是采集工具依赖，不是产品运行依赖；不使用 Docker 生成或替代桌面截图。

```bash
python3 backend/scripts/capture_desktop.py --guest USER@HOST --domain DOMAIN \
  --width 1440 --height 900 capture /var/tmp/new-pixiu-screen.png
python3 -m unittest discover -s backend/scripts/tests -v
```

输出目录须预先存在，已有图片拒绝覆盖；坐标须匹配实际分辨率。
Wayland 下须确认粘贴进入实际目标控件，不能假定 X11 剪贴板已同步。
新 PNG 通过 Git LFS 管理，逐文件记录尺寸、SHA-256、来源提交与验收边界。
空清单只表示待采集，不能作为图片完整性或发布就绪通过的依据。
