# PIXIU 技术方案及测试结果

版本：0.1.9

平台：银河麒麟桌面操作系统 V11

本稿包含当前实现、安装与操作实拍。最终候选的对比实验、量化评测及多设备和升级回滚实测仍待完成。


## PIXIU 技术方案

### 作品概述

PIXIU 帮助银河麒麟 V11 上的智能助手保存和复用长期记忆。用户可以查找过去的对话和工具结果，查看信息来源，更新已保存的知识，并让可信设备共享所需内容。

系统接收对话、工具结果、用户行为、手动配置和已识别的图片文本。图片识别依赖 OCR 扩展；当前安装包提供文本向量和向量数据库扩展，图片 OCR 仍需补齐运行依赖与实测。

### 解决的问题

跨会话和跨设备工作需要保留任务经验。例如，用户换一台电脑整理家庭账单时，需要找到原来的支出清单、沿用输出偏好，并确认金额来自哪条记录。

PIXIU 分别保存原始证据、知识、偏好和冲突记录。每条记录带有来源、使用范围、版本和敏感程度，便于检索、更新和追溯。

### 总体架构

用户在一个 PIXIU 主窗口中完成会话、记忆管理、设备管理和设置。桌面端基于 openKylin KylinAgent，agent-runtime 负责规划任务、调用工具和请求用户审批。

PIXIU 通过 MemoryProvider 接口为助手提供记忆读写能力。该适配层调用公共 API；后端负责数据接入、偏好提取、知识管理、检索、同步和遗忘。

后端按职责组织模块：记忆引擎处理接入、偏好、知识和安全；基础服务管理存储、检索、记忆流转及评测；同步模块负责设备间的更新；平台适配层调用系统 SDK。

### 记忆写入

系统先校验输入格式、整理字段、评估质量并检查敏感信息，再保存原始证据（evidence）。随后提取知识和偏好，建立实体关系及检索索引，并处理与已有知识的冲突。

助手产生的记忆保留会话、任务、轮次、工具调用、审批和时间信息。后端保存写入请求的处理结果，重复请求可复用已完成的结果。Provider 将待发送记录保存在本地队列中，以便处理发送失败。

### 记忆检索

系统同时按关键词、语义相似度和实体关系查找候选内容。关键词通道使用 BM25 评分；语义通道比较文本向量；关系图通道沿实体关系查找相关知识。

系统用 RRF 方法合并三个通道的排名，再按使用范围和时间筛选结果。对于家庭支出等结构化数据，系统还能汇总金额。结果附带知识和原始证据的引用，用户可据此核对来源。

检索和金额计算由后端执行。银河麒麟 V11 使用系统 Embedding 接口生成文本向量，并通过 Vector Engine SDK 保存、搜索和删除向量。

### 偏好与知识

偏好包括操作习惯、输出风格和安全策略。系统保存提取结果、置信度和版本历史，供后续任务使用。知识包括事实、工作流、案例和模板，并关联支持它们的原始证据。

知识编辑使用版本检查：提交时版本已经变化，系统会拒绝覆盖，用户需要重新读取后再编辑。冲突页面显示新旧内容、处理方式和时间，便于追查变化原因。

### 精准遗忘

用户用自然语言描述要遗忘的内容，界面先列出目标和相关记录数量。用户确认后，系统将目标知识标为已遗忘并移除向量。原始证据、关系和全文索引中的部分数据仍会保留。

每次预览生成一次性确认凭证，绑定目标及其版本。凭证过期或目标发生变化时，用户需要重新预览。共享知识还会生成删除记录（墓碑），用于向可信设备传播删除状态。

### 分布式记忆网络

每台设备保存本地副本，离线时仍可读取和写入。设备通过交换配对令牌建立信任；共享记录进入带签名的操作日志，私人记录保存在本机。系统分别使用 `shared:*` 和 `user:*` 标识这两种使用范围。

CRDT 根据版本信息合并同一条知识的并发更新。Gossip 将新操作传给在线设备；反熵对账在设备重连后比较记录并补齐遗漏。设备间通过双向证书验证身份，使用加密连接传输数据。

### 记忆流转

短期记忆保存当前任务上下文，中期记忆保存会话或项目状态，长期记忆保存可重复使用的事实、偏好和工作经验。

每轮任务开始前，MemoryProvider 按内容长度上限读取相关长期记忆。轮次完成后保存对话和工具结果，压缩、切换或结束会话时保存中期状态。助手可以调用记忆工具查询、记录和更新内容；遗忘执行由用户在界面确认。

### 安全与隐私

写入前，系统检查身份证号、银行卡号和手机号等敏感信息。敏感内容仅限本机使用，并从助手的记忆上下文中排除。敏感检测出错时，系统拒绝该次写入并返回错误。

设备配对、风险工具、遗忘和升级分别请求用户确认。模型密钥由 Runtime 的认证功能保存，用户通过设置界面配置模型服务。

### 平台适配

银河麒麟 V11 构建启用桌面 KylinSDK、Embedding SDK 和 Vector Engine SDK。启动检查确认依赖可用后，后端才进入就绪状态。Debian 兼容构建使用可移植实现，验证结果注明实际运行环境。

一个 `.deb` 包含桌面程序、内嵌管理界面、后端、MemoryProvider、Runtime 离线依赖、许可证和版本清单。后端在当前桌面用户的 systemd 会话中运行，以访问该用户的系统 AI 服务。

### 实现分工

PIXIU 实现记忆引擎、混合检索、记忆流转、分布式同步、MemoryProvider、系统 SDK 适配、管理界面和评测发布工具。KylinAgent 与 agent-runtime 提供会话、规划、工具和审批功能，各上游组件随包记录版本、来源和许可证。

### 应用价值

用户可以在新任务中调用过去的知识和工具结果，减少重复录入；通过来源和版本记录核对内容；在可信设备之间继续工作。家庭账单检索和跨设备工作流是两组具体应用，操作过程见应用案例。


## PIXIU 部署指南

### 安装环境

本指南适用于银河麒麟桌面操作系统 V11、amd64 架构，以下命令使用 `pixiu_0.1.9-1_amd64.deb`。软件安装后在当前桌面用户的会话中运行。

安装前，在系统“设置 → AI 模块管理”中启用 AI 能力，并确认软件源提供 Kylin Embedding、Vector Engine 和桌面 KylinSDK 运行组件。

### 校验安装文件

准备同一版本的软件包、摘要和签名文件，在下载目录运行：

```bash
sha256sum -c pixiu_0.1.9-1_amd64.deb.sha256
```

摘要用于检查文件是否完整，发布公钥和 Ed25519 签名用于验证文件来源。签名验证步骤见同版发布说明。当前 `submission` 中保存的 0.1.7 安装包属于历史归档。

### 安装与启动

本次 V11 环境已验证终端安装；系统的 `.deb` 默认打开程序为归档管理器。请在保存软件包的目录运行：

```bash
sudo apt install ./pixiu_0.1.9-1_amd64.deb
```

首次启动会创建当前用户的配置和数据目录，启动 `pixiu-backend.service`，并激活包内记忆插件。启动器会检查桌面程序和 Runtime 的版本是否兼容。

### 检查服务

在“设置 → 服务与能力”点击“读取服务与能力”，确认桌面与后端版本一致、数据库就绪，以及两个系统 SDK 正常运行。终端检查命令如下：

```bash
systemctl --user status pixiu-backend.service
curl -s http://127.0.0.1:8765/version
curl -s http://127.0.0.1:8765/health
curl -s http://127.0.0.1:8765/capabilities
```

| 检查项 | 0.1.9 的预期结果 |
|---|---|
| 后台服务 | `active (running)`，属于当前桌面用户 |
| 版本 | 产品 `0.1.9`、HTTP API `0.5.0`、数据库版本 `13` |
| 健康状态 | `ready`、数据库 `ok` |
| 系统 SDK | Embedding 与 Vector Engine 均为 `runtime=kylin` |

能力接口中的 `contest_ready=true` 表示当前系统与 SDK 已就绪。业务功能、性能和多设备结果还需按验收方案测试。

### 配置与数据位置

软件按 XDG 约定保存当前用户的配置和数据：

```text
$XDG_CONFIG_HOME/pixiu/pixiu.env
$XDG_DATA_HOME/pixiu/pixiu.db
$XDG_STATE_HOME/pixiu/
```

这些环境变量为空时，分别使用 `~/.config`、`~/.local/share` 和 `~/.local/state`。配置文件权限为 0600，仅供当前用户读写。模型密钥通过 Agent 设置界面交给 Runtime 保存。

### 多设备部署

每台设备安装与其架构匹配的同一版本软件。设备之间需要局域网互通，并允许 mDNS 发现和同步服务通信。按用户手册的令牌交换步骤建立双向信任。

三设备验证时，分别检查每台设备都信任另外两台，再完成共享写入、离线恢复和遗忘测试，记录各端结果。节点在线和队列为空只能说明当前连接及积压状态。

### 升级

在“设置 → 应用与升级”点击“检查更新”。软件依次下载文件、核对摘要和签名、请求系统授权、安装并检查服务。

升级会备份旧包、配置、数据库和同步身份。安装或健康检查失败时，系统尝试恢复备份并显示结果。升级成功后，保存工作并重启整个应用，让新程序生效。

### 卸载

```bash
sudo apt remove pixiu
```

普通卸载会保留当前用户的配置与记忆数据，重新安装后可继续使用。需要清理个人数据时，先备份所需内容，再核对要删除的数据目录。

### 故障排查

后端启动失败时，可重启服务并查看最近日志：

```bash
systemctl --user restart pixiu-backend.service
journalctl --user -u pixiu-backend.service -n 100 --no-pager
```

SDK 未就绪时，检查系统 AI 模块、SDK 运行组件和用户会话服务。修复依赖后重新启动 PIXIU。麒麟严格配置会在必需依赖不可用时停止启动并报错。

助手未加载记忆插件时，检查包内 Runtime 版本和启动错误，再重新打开 PIXIU。同步长时间没有完成时，检查设备连接、系统时间、暂停开关和待同步操作。

### 认识 PIXIU

PIXIU 在同一个窗口中提供“会话、记忆、设备、设置”四个入口。您可以让助手执行任务，保存和查找记忆，查看来源，并管理采集权限、可信设备和软件更新。

安装后，从应用菜单打开“PIXIU”，或在终端运行 `pixiu`。安装步骤和对应画面见部署指南。进入“设置 → 服务与能力”，点击“读取服务与能力”，检查桌面与后端版本、数据库状态和系统 SDK。

本例先录入“回答简洁”，再录入“回答详细”。当前要求变为详细回答，历史保留之前的简洁要求。界面中的 `compact` 表示简洁，`verbose` 表示详细。提取依据当前规则与证据，仍需核对是否符合原意。

## PIXIU 记忆流转说明

PIXIU 按使用时间和用途保存三层记忆。任务进行时使用当前上下文，任务结束后保留有用状态，经过处理的知识和偏好可供以后使用。

### 三层记忆

| 层级 | 保存内容 | 主要用途 |
|---|---|---|
| 短期 | 当前消息、计划和工具上下文 | 继续当前任务 |
| 中期 | 会话摘要、项目状态和中间结果 | 压缩上下文、切换和恢复会话 |
| 长期 | 偏好、事实、工作流、案例和模板 | 在后续任务中重复使用 |

### 保存记忆

系统校验对话或工具结果的来源和质量，检查敏感信息，然后保存原始证据。记忆引擎从证据中提取知识和偏好，处理冲突，再建立关键词、向量和关系图索引。

Provider 的 `sync_turn` 接口保存用户与助手的一轮对话，工具结果保留调用、审批和时间信息。发送记录先进入本地持久化队列，便于在发送失败后处理待办。会话压缩、切换或结束时，系统保存相应的中期状态。

### 读取记忆

每轮任务开始前，Provider 通过 `/agent/context` 请求相关长期记忆。系统按查询、会话、使用范围、时间和长度上限筛选内容，并排除敏感记录。

返回内容包含更新时间、冲突状态以及知识和原始证据的引用。助手将这些内容作为任务参考，系统指令和权限规则继续约束工具操作。

### 转为长期知识与清理

中期内容经过质量和敏感度等检查后，可转为长期知识，并关联原始证据。短期和中期记录按有效期清理；长期内容通过编辑或遗忘操作更新。冲突旧版用于追查处理过程。

### 在设备间传递

私人记忆保存在本机，共享记忆进入带签名的操作日志。系统用 CRDT 合并并发版本，通过 Gossip 向在线设备传递操作，并在重连后比较记录、补齐遗漏。

遗忘操作产生删除记录（墓碑）。同步合并时，该记录阻止较旧的内容重新变为可见；其他有效节点全部确认后，系统才回收墓碑载荷。最终三设备测试仍需验证离线重连和删除传播的实际结果。

### 保护用户数据

系统在写入前检测敏感信息，在检索和同步时检查使用范围。敏感内容限于本机，助手及受委派任务只取得权限允许的参考内容。

遗忘页面先显示目标和相关记录数量，用户核对后确认执行。系统隐藏知识并移除向量，原始证据和部分关联数据仍会保留。


## PIXIU 应用案例

家庭支出案例已在 0.1.9 上完成单机跨会话写入、召回和来源核对。跨设备工作流仍为待实测方案。

### 案例一：家庭支出检索

#### 场景

家庭成员通过对话、手动录入或已识别的图片文本保存多个月份的水、电、燃气账单。用户只记得模糊描述，希望立即得到准确金额，并能追溯原始清单。

#### 本次实际操作

通过助手输入公开合成账单：电费 210 元、水费 68.50 元、燃气费 156 元，要求计算并保存。助手调用记忆工具，将合计 434.50 元写入 `user:default`。另建会话后调用 PIXIU 记忆检索工具，返回相同明细和金额，再打开来源核对原文。

这次使用文本输入和助手计算，没有执行图片 OCR 或跨设备传输，也没有据此验证结构化金额聚合接口。


![家庭支出实拍：新会话返回已保存的账单，合计为 434.50 元。](../00-原始记录/01-图片记录/16-agent-recall-result.png)

家庭支出实拍：新会话返回已保存的账单，合计为 434.50 元。

#### 价值

用户可以用自然语言查询不同月份的账单。系统查找相关记录并按字段汇总金额，用户可打开来源检查每笔费用。

#### 遗忘

用户要求“忘记四月份账单”时，系统先列出目标和相关记录数量。用户确认后，知识从检索结果中隐藏，向量被移除，共享设备收到删除记录。原始证据和关系数据仍会保留。

### 案例二：跨设备工作流复用

#### 场景

用户在办公设备 A 上通过 Agent 完成资料检索、Shell 处理和报告整理，希望在设备 B 上继续使用已保存的工作步骤。私人数据保存在各自设备中。

#### 操作过程

1. Agent 在设备 A 调用工具，风险操作经过用户审批。
2. PIXIU 保存有价值的工具结果与操作顺序，形成工作流知识。
3. 共享工作流通过可信设备网络传播，私人记忆保留在设备 A。
4. 设备 B 离线期间仍可使用本地记忆并记录新偏好。
5. 设备恢复联网后，Gossip 与反熵完成增量对账。
6. 新会话中的 Agent 召回最终工作流，并依据设备 B 的本地偏好调整输出。

#### 并发与删除

两台设备并发修改同一共享知识时，CRDT 使用版本向量和确定性规则收敛。语义上互相矛盾的不同知识由冲突服务仲裁并保留审计记录。

任一设备删除共享条目后，墓碑会传播到其他可信节点。曾离线的旧副本重新加入时，系统根据删除记录继续隐藏相应内容。

| 赛题要求 | 家庭支出 | 跨设备工作流 |
|----------|----------|----------------|
| 多源接入 | OCR、对话、手动配置 | 对话、工具结果、用户行为 |
| 偏好记忆 | 查询与展示偏好 | 跨场景输出和工具偏好 |
| 知识记忆 | 账单事实与实体关系 | 工作流、案例和模板 |

## PIXIU 银河麒麟 V11 适配报告

### 适配结论

历史候选已在银河麒麟 V11 完成安装、用户服务启动和两个系统 SDK 的记忆读写验证。2026-09-08 检查确认，虚拟机运行 0.1.9，桌面与后端版本一致，两个 SDK 均使用麒麟实现。完整业务场景和性能仍需在最终候选上验证。

### 适配范围

| 层级 | 适配内容 |
|------|----------|
| 桌面 | Qt5、UKUI 主题、快捷键、通知、桌面入口 |
| 服务 | systemd user service、XDG 配置/数据/状态目录 |
| AI | Kylin Embedding SDK、AI Runtime、模型目录 |
| 向量库 | Kylin Vector Engine SDK、应用数据库生命周期 |

| 发布 | `.deb`、依赖、版本清单、SHA-256、Ed25519 签名 |

### 用户会话架构

系统 AI Runtime 的 Unix socket 按桌面用户 UID 隔离。PIXIU 后端因此运行在当前用户的 systemd 会话中，使 Embedding、Vector Engine、Agent Gateway 和本地数据都处于同一安全边界。

服务启动时验证 MainPID 所属 UID、loopback 端点身份、产品版本和数据库状态，避免连接到错误用户或占用相同端口的其他服务。

### Embedding SDK

系统通过 Kylin `coreai/embedding` 接口生成 gte-base 768 维文本向量。启动检查会确认模型、AI Runtime、客户端库和 SDK 调用可用，检查失败时服务停止启动并报错。

### Vector Engine SDK

产品使用系统 Vector Engine 的 `ConnectParam(appId)` 本地连接，通过 `LoadDBFile` 加载独立应用数据库，并执行集合创建、向量写入、搜索、删除、清理与断开。

启动预检在首条业务写入前验证数据库生命周期。产品 API 另行验证记忆写入、召回、遗忘和删除后不可见。

### KylinSDK 与界面

`KYSDK=ON` 构建启用系统快捷键、通知和 Qt 扩展适配。界面按浅色和深色主题设置文字、背景及状态颜色，消息区保持居中阅读宽度，长会话标题省略显示，键盘焦点和错误状态保持可见。

Debian 兼容构建使用标准 Qt 快捷键和系统托盘通知，用于验证基本桌面功能。麒麟 SDK 功能在 V11 环境单独测试。

### 安装与升级

单一 `.deb` 包含 PIXIU 后端、内嵌管理界面、记忆插件、KylinAgent 宿主适配、Runtime 离线依赖、原生扩展、SBOM 和 NOTICE。

安装前置脚本校验 V11 与架构；服务启动再次校验双 SDK；用户首次启动校验 Agent 与 Runtime。任一检查失败，系统都会停止对应步骤并报错。

图形升级在安装前校验资产摘要与独立签名，安装后核对 dpkg 版本、后端版本、数据库 schema、Provider 和服务健康。失败时恢复旧包、配置、数据和服务。

### 安全与可移植性

适配层负责调用平台 SDK。V11 严格配置要求使用原生实现；Debian 兼容配置提供基础写入、检索和测试功能，并记录实际使用的实现。

用户配置权限为 0600，设备同步使用可信配对、签名和 mTLS。敏感内容不进入共享域；模型密钥不写入源码、包、日志或测试证据。
