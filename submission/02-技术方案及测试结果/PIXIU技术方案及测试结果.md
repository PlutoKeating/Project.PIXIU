# PIXIU 技术方案及测试结果

版本：0.1.7

平台：银河麒麟桌面操作系统 V11

参赛单位：华南理工大学 PIXIU 团队


## 作品概述

PIXIU 是面向银河麒麟桌面操作系统 V11 的 OS Agent 分布式记忆系统。它把对话、工具结果、用户行为、手动配置和 OCR 内容统一转化为可检索、可追溯、可遗忘、可跨设备同步的长期记忆。

作品以 openKylin `kylin-agent` 与 `agent-runtime` 承载会话、规划、工具调用和审批。PIXIU 通过原创 MemoryProvider 接入 Agent 生命周期，核心成果是记忆引擎、混合检索、双 SDK 适配和去中心化同步网络。

## 解决的问题

传统 Agent 的记忆往往停留在单次会话或单台设备：工具结果难以复用，用户偏好缺少版本管理，知识更新容易冲突，历史信息难以准确召回，删除操作也难以在多设备间保持一致。

PIXIU 建立统一的 evidence、knowledge、preference 和 conflict 模型，使每条记忆都有来源、作用域、版本、敏感度和审计记录，并贯通写入、提取、检索、同步与遗忘全过程。

## 总体架构

```text
KylinAgent 桌面宿主
  └─ agent-runtime：会话、规划、工具、审批
       └─ PIXIU MemoryProvider：生命周期与记忆工具
            └─ PIXIU 公共 API
                 ├─ 记忆引擎：接入、偏好、知识、冲突、安全
                 ├─ 基础设施：存储、检索、流转、评测
                 ├─ 分布式同步：CRDT、Gossip、反熵、墓碑
                 └─ Kylin SDK：Embedding、Vector Engine
```

独立 PIXIU 控制台负责记忆查看、手动录入、偏好与冲突审计、设备配对、同步控制、精准遗忘和版本更新。它是管理界面，不替代完整 Agent。

## 核心数据链路

### 记忆写入

数据先经过格式校验、清洗、标准化、质量评分和敏感检测，再保存为 evidence。系统随后提取偏好与知识，建立实体关系，生成向量索引，并对新旧知识执行冲突仲裁。

每条 Agent 记忆记录 session、run、turn、tool-call、审批和时间信息。完成态请求采用持久化幂等收据，避免重试造成重复写入。

### 记忆检索

检索同时运行 BM25、向量召回和实体关系图三条通道，再使用 RRF 融合、作用域过滤、时间约束和结构化聚合生成结果。返回值携带 knowledge 与 evidence 引用，便于核验来源。

在线检索不依赖大模型生成，减少不确定性和端侧开销。银河麒麟 V11 生产画像使用系统 Embedding 接口生成文本向量，并通过系统 Vector Engine SDK 存储与检索。

### 偏好与知识

偏好分为操作习惯、输出风格和安全策略，支持自动提取、置信度、版本历史与跨场景复用。知识分为事实、工作流、案例和模板，支持实体关系、冲突审计和来源追溯。

### 精准遗忘

用户可用自然语言描述需要删除的内容。系统先展示影响范围，再经确认执行关联清理。共享记忆的删除会生成墓碑，并随同步协议传播，防止离线旧副本重新带回已删除内容。

## 分布式记忆网络

每台可信设备保存可独立工作的本地副本。设备通过确认式配对建立信任，并使用 CRDT 合并并发更新；Gossip 负责快速扩散，反熵负责重连后的完整对账。

只有 `shared:*` 作用域参与同步，`user:*` 私有记忆不离开本机。同步链路包含签名、mTLS、版本向量、操作日志、节点确认和墓碑回收，支持离线写入与最终一致。

## 记忆生命周期

短期记忆保存当前任务上下文；中期记忆保存会话或项目状态；长期记忆保存可跨会话复用的偏好、事实、工作流、案例和模板。

MemoryProvider 在每轮前召回受预算约束的长期记忆，在轮次完成后沉淀对话和工具结果，在压缩、切换和结束会话时保存中期状态。显式工具支持查询、记住、更新、遗忘和同步状态。

## 安全与隐私

系统在写入前识别身份证号、银行卡号、手机号等敏感信息。敏感内容不能进入共享域，也不会注入 Agent 上下文；检测异常时写入失败关闭。

设备配对、风险工具和系统升级均要求明确确认或系统授权。模型密钥由 Runtime 的隐藏认证入口管理，不进入源码、命令行、日志或交付证据。

## 平台适配

严格画像面向银河麒麟 V11，统一启用桌面 KylinSDK、Embedding SDK 和 Vector Engine SDK。非麒麟 Debian 环境提供明确的兼容画像，用于开发和基础功能验证，不与原生验收结果混淆。

软件以单一 `.deb` 交付，包含桌面宿主适配、Runtime 离线依赖、PIXIU Provider、后端、控制台、许可证、SBOM 和版本清单。安装后由桌面用户的 systemd 服务运行，以适配 AI Runtime 的用户会话边界。

## 原创边界

团队原创内容包括记忆业务引擎、存储与混合检索、记忆流转、分布式同步、MemoryProvider、双 SDK 产品接线、管理控制台、评测体系和发布门禁。

`kylin-agent`、`agent-runtime` 与两项系统 SDK 均明确标注来源、固定版本和许可证。PIXIU 不把上游通用 Agent 能力宣称为团队原创。

## 技术价值

PIXIU 将“能写能查的记忆接口”扩展为完整的记忆基础设施：记忆可进入 Agent 决策，可追溯到原始证据，可在多设备间安全收敛，也可通过自然语言被准确删除。

其差异化价值在于把 OS Agent 的长期记忆从单机会话缓存，提升为面向国产桌面系统的去中心化记忆网络。

## 认识 PIXIU

PIXIU 由 KylinAgent 和记忆控制台组成。KylinAgent 用于多轮对话、任务规划和工具执行；记忆控制台用于查看、录入、同步和删除记忆。

## 启动

安装后从应用菜单打开“PIXIU”，或在终端运行：

```bash
pixiu
```

首次启动会初始化当前用户的配置、数据库、后台服务和 PIXIU MemoryProvider。主界面可查看后端连接、版本和同步状态。

## 使用 Agent

1. 打开 KylinAgent，点击“新建会话”。
2. 在“云端模型”中选择已配置的官方直连模型。
3. 输入任务并发送；运行中可随时停止。
4. 风险工具出现授权提示时，核对动作后再决定是否允许。
5. 点击记忆来源可查看相关 evidence。

模型选择仅展示 DeepSeek、Anthropic 和 OpenAI 官方直连服务。API Key 应通过 Runtime 的隐藏认证入口配置，不要发送到聊天窗口或写入命令行。

## 管理记忆

在记忆面板中输入自然语言即可检索长期记忆。结果会显示内容、置信度、作用域、状态和来源。手动录入适合保存经过确认的事实、规则、工作流和配置。

偏好页展示操作习惯、输出风格和安全策略。每次变更保留版本历史，可查看系统何时、依据什么信息形成偏好。

冲突页展示新旧知识、裁决方式和时间。自动裁决不会删除旧证据，便于回溯；需要人工处理的冲突会保持显式状态。

## 连接多台设备

1. 在设备 A 打开“同步与设备”，生成配对请求。
2. 在设备 B 核对设备名称和六位 PIN。
3. 双方确认后完成可信配对。
4. 在节点列表中查看在线状态、积压操作和最近同步时间。

只有共享作用域的记忆会同步。私人作用域始终保留在本机。暂停同步不会影响本地写入；恢复后系统会自动反熵对账。

## 精准遗忘

1. 用自然语言描述要忘记的内容。
2. 查看系统列出的知识、证据和关联项。
3. 确认范围后执行遗忘。
4. 再次检索，确认内容不再出现。

共享记忆会生成删除墓碑并传播到可信设备。用户确认影响范围之前，系统不会执行删除。

## 更新软件

在“设置 → 关于与更新”查看当前版本、可用版本和组件兼容状态。选择更新后，系统依次完成下载、摘要与签名校验、系统授权、安装和健康检查。

更新成功后可立即重启客户端。若安装或健康检查失败，界面会明确显示恢复结果；在恢复状态确认前不要继续写入重要数据。

## 隐私控制

行为采集可在设置中关闭。敏感信息默认限制在本机，不进入共享域和 Agent 上下文。设备配对、风险工具、遗忘和升级都有独立确认步骤。

## 常见问题

| 现象 | 处理方式 |
|------|----------|
| Agent 无法连接记忆服务 | 检查设置页服务状态，再运行 `systemctl --user status pixiu-backend.service` |
| 设备无法发现 | 确认同一局域网、同步已开启、防火墙允许服务通信 |
| 搜索结果为空 | 核对作用域、时间范围和关键词，确认记忆已完成写入 |
| 更新被拒绝 | 核对网络、软件架构、版本与签名文件是否匹配 |
| 遗忘后其他设备仍显示旧值 | 等待设备上线并完成反熵对账，再刷新状态 |



## 三层记忆

| 层级 | 保存内容 | 生命周期 | 主要用途 |
|------|----------|------------|----------|
| 短期 | 当前消息、计划、工具上下文 | 当前任务 | 保持即时推理连续 |
| 中期 | 会话摘要、项目状态、中间结果 | 小时至数日 | 承接压缩、切换与恢复 |
| 长期 | 偏好、事实、工作流、案例、模板 | 跨会话 | 检索复用与持续个性化 |

## 写入流程

```text
对话或工具事件
  → 来源与质量校验
  → 敏感检测
  → evidence 持久化
  → 偏好/知识提取
  → 冲突仲裁
  → 图、关键词与向量索引
  → 按作用域进入同步
```

`sync_turn` 保存完整用户与助手轮次；工具结果记录 tool-call、审批和时间来源；`on_pre_compress` 保存有界中期状态；会话切换或结束时更新 session 与 run 状态。

## 召回流程

每轮任务开始前，`prefetch` 调用 `/agent/context`。系统依据 query、session、scope、时间和字符预算检索长期记忆，并过滤敏感内容和不可见作用域。

召回结果携带新鲜度、冲突状态、knowledge 与 evidence 引用。Runtime 将其作为不可信上下文注入 Agent，避免记忆内容越权改变系统指令。

## 晋升与清理

中期内容经过质量、重复度、价值和敏感度判断后，可晋升为长期知识或偏好。晋升保留原始 evidence，不以摘要替换来源。

短期和中期记录按 TTL 清理；长期内容通过显式遗忘或版本更新处理。冲突旧版保留为可审计状态，不参与默认召回。

## 多设备流转

私人记忆留在本机，共享记忆进入签名操作日志。CRDT 负责并发合并，Gossip 负责快速扩散，反熵负责离线设备重连后的完整对账。

遗忘生成墓碑。离线旧副本重连时先接收墓碑，旧创建或更新操作不能覆盖因果上更新的删除状态；全部有效节点确认后，系统才回收墓碑载荷。

## 安全规则

- 先检测敏感信息，再占用幂等收据或写入数据库。
- 敏感内容不得进入共享作用域或 Agent 上下文。
- 作用域过滤在检索和同步两侧同时执行。
- 委派给子 Agent 时只传递任务所需的最小记忆。
- 遗忘必须先展示影响范围，再由用户确认。



## 案例一：家庭支出全局检索

### 场景

家庭成员通过图片、对话和手动录入保存多个月份的水、电、燃气账单。用户只记得模糊描述，希望立即得到准确金额，并能追溯原始清单。

### 过程

1. OCR 结果经过格式标准化、质量评分和敏感检测。
2. 系统提取月份、类别、商户和金额，建立实体关系。
3. 内容写入关键词、向量和关系图三类索引。
4. 用户询问“上个月水电燃气花了多少”。
5. 系统按时间范围召回账单，并对结构化金额聚合。
6. Agent 返回分类明细，并附原始 evidence 来源。

### 价值

传统文件搜索依赖精确关键词，无法直接回答跨图片、跨月份的模糊问题。PIXIU 将语义召回与结构化计算结合，使回答既能理解自然语言，也能核对到原始记录。

### 遗忘

用户要求“忘记四月份账单”时，系统先展示相关知识、证据和关联项。确认后完成级联遗忘，并验证该月记录不再参与检索。

## 案例二：跨设备工作流复用

### 场景

用户在办公设备 A 上通过 Agent 完成资料检索、Shell 处理和报告整理，希望回到设备 B 后继续复用该流程，同时保证私人数据不会传播。

### 过程

1. Agent 在设备 A 调用工具，风险操作经过用户审批。
2. PIXIU 保存有价值的工具结果与操作顺序，形成工作流知识。
3. 共享工作流通过可信设备网络传播，私人记忆保留在设备 A。
4. 设备 B 离线期间仍可使用本地记忆并记录新偏好。
5. 设备恢复联网后，Gossip 与反熵完成增量对账。
6. 新会话中的 Agent 召回最终工作流，并依据设备 B 的本地偏好调整输出。

### 并发与删除

两台设备并发修改同一共享知识时，CRDT 使用版本向量和确定性规则收敛。语义上互相矛盾的不同知识由冲突服务仲裁并保留审计记录。

任一设备删除共享条目后，墓碑会传播到其他可信节点。曾离线的旧副本重新加入时，也不能使已删除内容复活。

## 案例与赛题要求映射

| 赛题要求 | 家庭支出 | 跨设备工作流 |
|----------|----------|----------------|
| 多源接入 | OCR、对话、手动配置 | 对话、工具结果、用户行为 |
| 偏好记忆 | 查询与展示偏好 | 跨场景输出和工具偏好 |
| 知识记忆 | 账单事实与实体关系 | 工作流、案例和模板 |

| 安全遗忘 | 按月份精准删除 | 墓碑防复活 |
| 记忆流转 | OCR 进入长期知识 | 工具结果沉淀与复用 |



## 适配结论

PIXIU 采用 `kylin-v11-native-x86_64` 严格画像构建，在银河麒麟桌面操作系统 V11 上完成单包安装、桌面用户服务运行、Kylin Embedding 与 Vector Engine 产品链验证。

## 适配范围

| 层级 | 适配内容 |
|------|----------|
| 桌面 | Qt5、UKUI 主题、快捷键、通知、桌面入口 |
| 服务 | systemd user service、XDG 配置/数据/状态目录 |

## 用户会话架构

系统 AI Runtime 的 Unix socket 按桌面用户 UID 隔离。PIXIU 后端因此运行在当前用户的 systemd 会话中，使 Embedding、Vector Engine、Agent Gateway 和本地数据都处于同一安全边界。

服务启动时验证 MainPID 所属 UID、loopback 端点身份、产品版本和数据库状态，避免连接到错误用户或占用相同端口的其他服务。

## Embedding SDK

产品链通过 Kylin `coreai/embedding` 接口生成 gte-base 768 维文本向量。严格启动预检要求模型目录、AI Runtime、客户端库和 SDK 调用全部可用，否则服务拒绝就绪。

## Vector Engine SDK

产品使用系统 Vector Engine 的 `ConnectParam(appId)` 本地连接，通过 `LoadDBFile` 加载独立应用数据库，并执行集合创建、向量写入、搜索、删除、清理与断开。

启动预检在首条业务写入前验证数据库生命周期。产品 API 另行验证记忆写入、召回、遗忘和删除后不可见。

## KylinSDK 与界面

`KYSDK=ON` 构建启用系统快捷键、通知和 Qt 扩展适配。界面使用语义颜色令牌跟随浅色与深色主题，消息区保持居中阅读宽度，长会话标题省略显示，键盘焦点和错误状态保持可见。

缺少专有桌面组件时，Debian 兼容画像使用标准 Qt 快捷键与系统托盘通知。该路径用于可移植性，不替代 V11 原生结果。

## 安装与升级

单一 `.deb` 包含 PIXIU 后端、控制台、Provider、KylinAgent 宿主适配、Runtime 离线依赖、原生扩展、SBOM 和 NOTICE。

安装前置脚本校验 V11 与架构；服务启动再次校验双 SDK；用户首次启动校验 Agent 与 Runtime。三层检查均采用失败关闭。

图形升级在安装前校验资产摘要与独立签名，安装后核对 dpkg 版本、后端版本、数据库 schema、Provider 和服务健康。失败时恢复旧包、配置、数据和服务。

## 安全与可移植性

专有 SDK 均位于适配层之后。严格 V11 画像禁止静默降级；Debian 画像保留基础写入、检索和测试能力，并明确报告实际 runtime。

用户配置权限为 0600，设备同步使用可信配对、签名和 mTLS。敏感内容不进入共享域；模型密钥不写入源码、包、日志或测试证据。
