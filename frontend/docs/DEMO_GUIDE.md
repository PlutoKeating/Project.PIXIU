# PIXIU 前端演示说明（内部演示稿）

> 模块：Module A · 唯一 PIXIU 桌面宿主中的会话与记忆管理界面。
> 版本依据：已安装包的构建清单、运行文件与对应自动工作流，不以文档中的固定版本号代替核对。
> 适用对象：答辩、现场操作、用户手册和提交材料截图准备。
> 目标平台：银河麒麟 OS V11；Debian 系通用结果与麒麟 SDK 结果分别记录。
> 配套范围：根 `docs/UNIFIED_FRONTEND_PLAN.md`、`docs/API.md`、`docs/DELIVERY_PLAN.md`。

正式产品使用 openKylin Agent 作为唯一宿主，会话、记忆、设备和设置属于同一应用。
本指南是操作与取证路线，不是“全部验收通过”的声明。模型规划、工具执行、跨会话
复用、真实多设备与完整升级须各自提供实际证据，不能用管理页截图替代。

## 1. 演示前置条件

1. 从自动 Release 获取匹配平台与架构的完整 PIXIU 安装包，按交付说明核对摘要、
   签名及构建来源后安装。使用实际下载文件，不照抄某个旧版本文件名：
   `sudo apt install ./<已核验的安装包>.deb`。不另外安装第二个前端包。
2. 在正常桌面用户会话通过开始菜单中的 PIXIU 或 `pixiu` 启动。
   启动器负责准备用户服务和 Agent 集成；无需为已安装产品另起手工 HTTP 服务。
   不以 root 启动桌面应用，不临时重定向到演示服务器。
3. 在“设置 → 服务与能力”读取版本、服务和 SDK 状态。核对安装文件与正在运行的
   宿主属于同一构建；安装更新后仍存活的旧进程不能用于新版本截图。
4. 只使用经过同意的合成演示数据及专用目录。记录原采集配置，避免收集私人目录。
   模型会话需配置实际可用的模型服务，并核对联网说明；直接记忆检索不要求大模型。
5. 原生截图从真实 UKUI 桌面入口取得。记录系统、会话类型、缩放、主题和分辨率；
   不把离屏组件测试或 Debian 兼容行为记成麒麟 V11 验收。

## 2. 建议演示顺序（按场景串场）

### 2.1 录入记忆（走通 `/memory/write`）

1. 进入“记忆 → 检索与录入”，选择范围，点击“录入记忆”。
2. 在正式表单填写合成内容并核对范围，提交一次；按实际响应判断成功或失败。
3. 成功后使用内容中的唯一关键词检索，选择来源核对原始正文与范围。
   保存真实返回的证据标识，用于后续偏好提取和取证关联。
4. 失败时保留输入并核对错误；不把按钮点击、气泡或系统通知当成写入证明。

当前正式录入是文本表单，不提供图片拖入即完成 OCR 的演示承诺。
空态与错误态应分别截图；不要为制造离线画面擅自停止用户正在使用的服务。

### 2.2 遗忘（走通 `/forget` 两段式确认）

1. 进入“记忆 → 安全遗忘”，选定范围，输入仅针对合成样本的描述。
2. 点击“预览匹配目标（不执行遗忘）”，逐项核对目标、版本及关联预估。
3. 先演示“取消并清除本页预览”，确认没有发送执行请求。
4. 确需演示执行时重新预览，核对后明确确认，再检索验证实际结果。
   修改条件或凭证到期必须重新预览；网络失败可能已部分生效，不重复确认。

遗忘隐藏知识并删除其向量，共享知识生成同步墓碑。关联数量不是原始证据、
关系和全文载荷已物理擦除的证明；本界面没有撤销按钮，跨设备送达另行验证。

### 2.3 冲突审计（走通 `/conflicts`）

进入“记忆 → 偏好与审计”，切换“冲突审计”并刷新。
选择真实记录，展示字段、原内容、新内容、处理结果和严重程度。
本页为只读审计，不提供人工裁决或回滚；“待人工确认”不是已经处理。
没有记录时展示真实空态，加载失败不能包装成“暂无冲突”。

### 2.4 偏好历史（走通 `/preference/{id}/history`）

进入“记忆 → 偏好与审计”的“偏好与历史”，刷新当前范围列表，
选择实际偏好读取历史，核对版本、值和记录时间。不得预先承诺固定版本数量；
无历史或标识异常按界面实际提示说明。

### 2.4.5 偏好提取（走通 `/preference/extract`，2026-08-10 新增）

先检索并取得有效来源，或完成一次正式录入，再进入“偏好与审计”点击
“从当前证据提取偏好”。按钮使用当前来源或最近成功录入的证据，不从无关日志猜 ID。
记录实际返回数量，再刷新偏好列表核对；零条也是合法结果。
切换范围或来源失效时重新取得证据，不把通知或提取请求已发出当成持久化成功。

### 2.5 检索与同步（后端已实现，联调依赖真实环境）

- 直接检索：在“记忆 → 检索与录入”选择范围，查询合成样本，展示命中、
  空结果、正文来源及高级原始数据。范围切换会清除旧结果，必须重新检索。
- Agent 会话：在“会话”执行实际多轮任务，单独展示工具与记忆复用证据；
  “本会话记忆来源”是会话级来源集合，不是每句回答的逐句引用。
- 设备：在顶级“设备”页读取节点、发现与网络状态。正式配对入口为交换令牌：
  两台设备各自生成 PIN 保护令牌或二维码令牌，经可信渠道交换并分别提交。
  本机建立信任不代表对端已信任，也不代表内容已经同步；二维码页不提供摄像头扫描。
- 同步结果：使用同一共享范围的合成样本，分别核对两端实际查询与状态。
  不以发现列表、单端配对成功或本地事件计数替代跨设备传输验收。

## 5. 两种运行模式（2026-08-10 补充）

### 模式 A：演示桩（无后端、无麒麟 SDK，开发机可完整演示 UI）

此标题保留用于原有章节定位。测试替身仅用于开发回归，不作为正式演示模式，
不启动已退役应用，也不把替身响应或离屏画面加入产品截图、答辩和用户手册。
管理组件回归入口是 `frontend/cmake/Management.cmake` 的
`PIXIU_MANAGEMENT_TESTS=ON`；结果只能支持其具体测试覆盖范围。

### 模式 B：真实后端（麒麟环境或已装依赖的开发机）

已安装产品直接从系统菜单或 `pixiu` 启动同一宿主及随包服务。
开发者服务调试与用户安装流程分开，详细构建与环境配置以根开发和交付文档为准。
通用画像使用可测试的兼容实现，原生画像要求官方 SDK；两类结果分别记录。
页面可打开、HTTP 可连通、SDK 已链接和业务实际完成是不同证据层，不能互相替代。

### 2.6 桌面集成观感（真实 UKUI 会话人工验证）

- 在“设置 → 应用与升级”核对当前唤起快捷键及“全局/仅应用内”状态，
  再在其他应用前台实际按键验证恢复同一进程；默认 Ctrl+Alt+P 不是必然注册成功。
- 托盘、开始菜单与命令入口应指向同一宿主。主窗口关闭走退出保护，
  有未保存编辑时分别验证保留和明确放弃，不展示第二套常驻小窗口。
- 主窗口置顶入口已实现：原生路径等待窗口管理器状态确认，兼容路径明确提示
  实际效果取决于窗口管理器。f2246f0 原生包已验证置顶、遮挡、取消及最小化恢复；
  最终演示包仍须核对同版运行文件，不直接沿用候选诊断图。
- 系统通知按正式 HostTray 的冲突/偏好提示路径验证；不能用测试 WS 弹窗替代真实业务事件。
- 深浅主题、长文本、键盘焦点、缩放和多屏逐项操作并截图，不引用退役窗口的验收结论。

## 3. 已知问题与限制（演示前必读）

| 项 | 当前边界 | 演示要求 |
|----|----------|----------|
| 直接检索与 Agent | 管理检索不等于 Agent 规划或回答正确 | 分别提供查询来源与实际任务证据 |
| 配对与同步 | 单端信任不等于双端传输 | 双端实际样本验证，公开素材不含有效令牌/PIN |
| 采集 | 正式页提供目录与行为配置；剪贴板和自动截图未实现 | 保存响应与实际采集日志分开核对 |
| 图片 OCR | 不能由配置字段、图片预览或文本直读证明可用 | 核对实际安装绑定与图片识别结果，缺失则明确未验证 |
| 遗忘 | 不承诺物理擦除所有关联数据或全部设备副本 | 展示真实预览、确认与结果，不虚构撤销 |
| 快捷键与置顶 | 能力依赖当前桌面与 SDK 状态 | 读取实际状态并真实操作，不以控件存在证明生效 |
| 主题、多屏、架构 | 单一环境结果不能外推全部矩阵 | 标注实际已测平台；未测项保留未完成 |
| 升级 | 组件测试不代表整包升级/回滚全部通过 | 核对自动产物、签名、安装、重启和用户数据 |

## 4. 演示口径建议

按“真实场景 → 实际操作 → 后端结果 → 可核验来源 → 能力边界”组织讲解。
错误必须如实解释，不能统一称为设计占位；未完成能力不安排伪造成功画面。
安装、启动、直接检索、Agent 会话、设备与升级分组取证，但始终来自同一正式应用。
截图中的示例内容明确注明为合成数据；数据说明可放在配套清单，不改写软件画面。

## 6. 批次②演示脚本：目录监视闭环（2026-08-26）

目录采集的有效证明是：批准的配置已保存，指定合成文件被当前采集链路处理，
返回的知识/证据能实际检索，并能核对采集时来源。单条 `ingested` 日志不足以证明
目标图片 OCR 成功，也不能把随后文本样本的成功记到图片识别上。

### 6.1 准备（复用 §5 模式 B：真实后端）

在正常桌面启动已安装 PIXIU，进入“设置 → 采集与隐私”，先读取已保存配置并记录。
准备专用、允许采集的目录及带唯一标识的合成文本；不要添加整个个人目录。
目录权限、文件类型和实际 SDK 能力都影响结果。若演示图片，先单独确认 OCR
运行能力，不通过安装 Pillow 或生成图片来推断识别可用。

### 6.2 一键闭环脚本

本节不提供会覆盖用户配置、自动更换样本或仅凭近期日志判成功的一键脚本。
按正式界面完成以下可核验步骤：

1. 读取并保留原配置，只添加已授权演示目录，启用所需来源并保存；保存失败即停止。
2. 放入一个带唯一标识的合成文件，记录该文件身份、内容摘要和操作范围。
3. 刷新采集日志，核对与这个文件匹配的处理记录及失败信息，不拿其他目录事件充数。
4. 用唯一关键词检索，打开实际返回的来源，核对正文、证据标识及采集来源。
5. 演示结束恢复原采集配置并重新读取核对；关闭采集不会删除已保存记忆。
   样本清理如需遗忘，使用正式预览与明确确认流程，不直接删除用户数据库。

图片与文本是两项独立测试。图片失败应记录失败原因，不自动换成文本后宣称
图片闭环成功；超时也不能直接推断“没有 OCR”。

### 6.3 前端可视化对照（与脚本并行演示）

1. “设置 → 采集与隐私”：展示实际保存配置、启用来源及明确的未实现能力提示。
2. 在同页点击“刷新采集日志”，核对当前样本记录；日志分页和刷新不会自动保存配置。
3. “记忆 → 检索与录入”：查询当前样本，选择来源并展示正文和采集时路径。
   路径记录不保证原文件仍存在或内容未变化，缺失路径不能由标题推断。
4. 保存或读取失败时展示真实错误与保留的编辑，不声称“离线本地生效”或自动对账。
   需要故障演示时使用独立测试会话，不能中断用户正在进行的工作。

### 6.4 截图留证建议

截图必须来自已核验安装版本的真实桌面像素。保持同组分辨率、缩放、主题、
窗口尺寸和布局，保留必要的软件及系统上下文；不为方便截屏切换会话后仍声称
验证了原来的 Wayland 行为。按原有效构图复拍的安装/启动图与功能补充图分别管理。

建议形成以下素材组，作为后续手工加入 PPT、操作手册、软件介绍和提交材料的原图：

- 安装与启动：已核验安装包、实际安装界面/终端、完成状态、开始菜单入口、
  首次启动、服务与版本信息；系统授权画面不得包含密码。
- 会话：正常任务、工具过程、完成结果、多轮衔接、本会话记忆来源及失败提示。
- 记忆：录入表单与成功后回查、范围选择、检索结果、空态、正文来源、
  文件采集来源、高级原始数据、编辑前后核对。
- 偏好与冲突：实际列表、选中历史、提取结果、只读字段对比与无记录状态。
- 安全遗忘：目标预览、取消、明确确认后的真实结果；仅使用合成样本。
- 设备：未配对、发现、令牌表单未生成状态、双端信任与实际同步结果；
  不公开有效二维码、令牌、PIN、私人地址或设备隐私。
- 隐私与采集：读取配置、授权目录、保存结果、当前样本日志、暂停及真实失败。
- 洞察与简报：实际候选、所选日期与正文、无数据和失败状态。
- 桌面与设置：快捷键状态、真实置顶/取消置顶、托盘、退出编辑保护、
  深浅主题、键盘焦点、关于、联网说明和许可证。
- 升级：实际版本检查、下载/校验、系统授权、安装结果、受控重启及可验证失败路径。

每张记录用途、源提交/包体、操作前提、画面状态、示例数据性质和验证结果。
失败与未完成项如实标注；图库未完成前不引用不存在的文件。
不保留过时界面截图或另建旧版展示归档，不用测试替身、AI 生成图或修改像素补造界面。
