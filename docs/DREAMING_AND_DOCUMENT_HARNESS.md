# 文档读取与 Dreaming 实施契约

2026-09-10 用户新增要求。与 SOURCE_MIGRATION_AND_PRODUCT_PLAN.md 一同执行；本文件覆盖先前图片专用草稿/模型选择方案。当前为实施契约，不代表所有能力已经完成。

## 产品行为

用户附加资料后正常对话，不再选解析器、图片模型、分块范围或向量数据库操作。授权目录里的资料由后台 dreaming 处理；用户能看到进度和结果，无需逐份打开录入窗口。当前聊天模型是唯一模型选择来源。图片与扫描 PDF 仅在当前模型支持多模态时读取，否则相关设置显示不可用，不借助 OCR 伪装知识理解。

Dreaming：非用户直接附加到当前对话的资料，由受控 Agent 工作流程完成解码、分批理解、检索已有记忆、形成整理方案、执行获准的知识变更及报告。它不等同于 watcher 自动调用 structure，也不等同于给任意通用 Agent 一个目录或数据库连接。

## 模块与归属

| 模块 | 归属 | 职责 |
|---|---|---|
| Document decoding | backend/foundation/documents | 文本、PDF、Office 解码；保留段落/页/表/单元格/幻灯片/图片位置，输出统一内容清单；不调用模型、不写知识 |
| Document registry | backend/foundation/documents | 接收用户附件或获授权目录事件，生成 document_id、内容版本与范围；模型只获得 ID，不获得任意路径能力 |
| MCP tools | backend/agent/mcp | 标准 MCP 适配，同一组受控文档/记忆操作用于对话与 dreaming；通过公共契约访问服务，不导入私有仓储 |
| Dreaming harness | backend/agent/dreaming | 驱动模型工具循环、限定工具与任务权限、分批覆盖、检查计划并执行获准操作；不加载终端/网络浏览等通用工具 |
| Memory operations | 既有 backend/engine 与 foundation API | 版本检查、敏感处理、知识/证据、偏好/冲突、向量物化与同步；模型不能绕过这些服务直接操作数据库 |
| Product presentation | frontend/src | 附件、设置能力状态、计划审批与主动报告；解析/存储内部参数不进入普通用户操作流程 |

## 固定工具接口

- `document_describe(document_id)`：格式、版本、内容清单、未解析项及处理状态。
- `document_read(document_id, cursor)`：有位置与来源标识的内容块及下一游标。模型不能指定本机路径或 URL。
- `memory_search(query)`：harness 注入已授权读取范围，不接受模型扩张权限。
- `memory_plan(operations, source_refs)`：提出创建/纠错/合并建议，每项带证据引用；未知字段、未知操作、错误来源版本拒绝。
- `memory_apply(plan_id)`：只执行 harness 中已验证且获准的计划。向量更新由既有知识物化服务执行，不暴露 SQL、集合名、任意向量删除或文件操作。
- `dreaming_report(summary)`：报告已经发生的操作及未完成内容；完成状态由覆盖清单和实际操作结果决定，模型不能自行宣称成功。

工具外不提供 shell、Python 执行、外网抓取、任意路径读取或原始数据库访问。文档中的提示、宏、外链和嵌入对象均是资料，不得成为权限或可执行指令。文档引用不会授予额外文档访问权。

## 内容完整性

首批正式格式包含 TXT/MD/CSV、PDF、DOCX/XLSX/PPTX；DOC/XLS/PPT、ODT/ODS/ODP、RTF 同样通过固定 Kreuzberg 4.10.3 原生解码，不执行宏或外链；引擎与本地库由安装包携带，全程 headless，不依赖 LibreOffice、Poppler 或运行时下载。每个解码器必须报告实际覆盖与不支持内容，不能静默跳过后标记成功。

Office 需要覆盖正文、表格、工作表及单元格、幻灯片及备注、嵌入图片；PDF 区分文本层与扫描页面。正文与图片可能混合，不能仅凭文件扩展名认定为纯文本。公式保留表达式和已有缓存值，不自动执行工作簿。

大文件分批读取，每块包含 document_id、内容版本、位置和 chunk_id。上下文容量决定每批大小，不决定丢弃多少内容。任务记录已处理块、未处理块、失败项和记忆证据引用；全部必要内容处理完毕后才能标记完成。不把“模型看到摘要”说成“模型看过全部原始内容”。

多模态不可用时，图片/扫描页面保持未读取状态；纯文本部分可处理，但文件含未处理内容时不能报告整份资料已经完整整理。

## 授权与执行

授权目录及用户主动上传构成资料读取授权；后台 dreaming 只在这些来源内运行。普通私人记忆创建与索引维护在已批准的整理计划范围内自动执行。越出既有授权的共享、删除、信任修改等必须经过相应审批，不通过模型输出中的 approved=true 自授权限。

模型输出只是一份建议。harness 校验工具白名单、文档/范围授权、来源版本、内容覆盖和操作类型，再交给真实服务执行。用户可暂停后台整理；取消授权后尚未执行的任务不继续读入。工作失败保留明确状态，不虚报已记住，也不要求用户反复选择工程参数。

OCR 仅是敏感内容定位/标注辅助工具，不生成知识正文，也不独立保证敏感信息识别完整。

## 实施顺序与退出标准

1. 先稳定正在修改的当前模型同步、附件/目录共用入口，撤掉额外模型选择；正式宿主构建通过。
2. 实现统一文档结构与 Office/PDF 解码器；混合内容、多页和超出单次上下文的资料有覆盖证明。
3. 提供实际 MCP 工具及自动注册；对话通过工具读取资料，不堆叠另一套解析代码。
4. 接入 dreaming 工具循环和受控计划执行，替换 watcher 直接入库；测试模型只能通过规定工具影响记忆与向量索引。
5. 实现任务状态、自动页面更新与主动工作报告；减少重复确认，保留实质性授权。
6. 运行跨格式、能力关闭、取消授权、文档恶意指令和受控记忆操作测试；再更新 Runtime 锁、同提交安装包和源码交付物。真实模型测试与模拟模型测试分开记录。

新增需求扩展了先前图片账单范围；不能沿用之前“图片入口测试通过”作为 Office、MCP 或 dreaming 已完成的证据。
