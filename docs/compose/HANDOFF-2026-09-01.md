## 3. 一键升级已实现并随 v0.1.6 发布的功能

完整链路已就绪（U-1..U-4），全在前端 + 后端 config：
1. **检测**：`UpgradeController` 独立 QNetworkAccessManager 拉 `GET https://api.github.com/repos/PlutoKeating/Project.PIXIU/releases/latest` → `ui::compareVersions` 对比远程 vs 本地 `applicationVersion`
2. **下载**：有界流式下载到唯一临时文件（QSaveFile 原子写）→ 分块 SHA-256 + 资产文件名绑定校验
3. **安装**：`pkexec /usr/lib/pixiu/install-update <deb> <sha256>`；特权 helper 将下载复制到 root-only 文件并二次校验，再由非交互 `dpkg` 保留设备配置完成安装 → 成功提示手动重启
4. **安全**：HTTPS + SHA-256 双校验、每跳 GitHub host 白名单、大小限制、特权边界二次校验、15s 超时、`FailedReason` 枚举解 i18n 耦合
5. **UI**：CheckUpdateDialog 一键升级（当前/远程版本、状态环、进度条、检查/一键升级/取消按钮），PixiuApp 懒创建共享 controller + `setUpgradeControllerForTest`
6. **后端安全**：同步属性拒绝公开占位符但核心 API 可降级启动；安装时以可恢复 journal 生成随机口令并无损重加密既有身份

**测试**：前端 36/36 ctest 全绿；后端相关 89 passed（config/sync/di/sync_settings 等）。

## 6. 关键背景与约束（勿违背）

- **模块边界**：`frontend/` 只改前端，`backend/` 只改后端；批次②③④都已完成。改 backend 前需用户确认（项目规则）。
- **版本管理宗旨（用户核心规则）**：每次发布严格版本增量（CMakeLists/functions.sh/debian control 三处同步）+ .deb.sha256 一致性 + 旧版可 dpkg 增量升级（postinst venv 复用 + conffile 幂等追加，T24 已修）。
- **产品名**：PIXIU（貔貅为中文名/文化意象）；**问候语不得把用户称貔貅**（欢迎页用 `ui::displayUserName()` 动态取系统全名）。
- **push**：非 main 可推；main 仅在用户最新显式授权下推送；禁止未二次确认的 force push。
- **转公开前安全前置**：已完成敏感审计（无真实凭据）；后端 guard（`fc1b139`）已加，转公开前须补门禁。
