# D-06 PIXIU 用户手册工作稿

- 适用版本：0.1.7 功能基线
- 状态：记忆控制台与 KylinAgent 新界面操作已覆盖；真实 Agent 交互待取证补图

## 使用入口

完整作品由 openKylin Agent 宿主和 PIXIU 记忆能力组成；独立 PIXIU 控制台用于
查看/录入记忆、偏好与冲突、设备配对、同步控制、隐私/遗忘和版本更新。控制台的
检索窗口不是完整 Agent 对话。

KylinAgent 顶部显示“PIXIU / KylinAgent · 分布式记忆工作台”，左侧是“会话与记忆”
列表，右上角“云端模型”用于选择已配置的云端推理服务。点击“＋ 新建会话”后，在
底部输入框描述任务并选择“发送”；运行中可选择“停止”。空状态不会显示数据库路径
或用户目录。界面跟随系统浅色/深色主题；如文字、下拉框或按钮不可读，应停止验收并
按部署指南确认安装的是包含 ADR-0004 补丁的同版候选。

## 核心操作

1. 在 Agent 中提出多轮任务；Agent 可自主召回相关记忆并显示来源。
2. Agent 调用 Shell、搜索或其他工具时，风险操作先请求授权，结果按价值进入记忆。
3. 在 PIXIU 控制台查看 evidence、偏好历史和冲突审计，或手动录入可信知识。
4. 在同步页发现并确认可信设备；选择共享 scope，私人 scope 默认不离开本机。
5. 用自然语言发起遗忘，核对影响范围并二次确认；共享遗忘通过墓碑传播。
6. 在设置页查看版本、发行说明和组件兼容状态，并执行一键升级。

升级只有在安装包身份、实际安装版本、后端版本、数据库 schema/就绪状态和包内
Provider 版本全部一致后才显示成功；此时选择“立即重启”，客户端会有序退出并启动
已安装的新版本。若无法调度重启，窗口会保留并提示手动重新打开 PIXIU。若界面提示
“升级后健康检查失败”，不要把当前
状态视为已恢复：只有“已自动恢复上一版本和数据”才表示恢复成功；若提示“升级恢复
失败”，应停止操作并按部署指南检查服务。更新缺少或无法通过 Ed25519 独立签名时
会在安装前拒绝；
最终 V11 图形升级后的重启与全链路仍属于发布门。

## 隐私、权限与错误恢复

行为采集必须知情且可关闭。写入时自动识别身份证号、通过校验的银行卡号和手机号：
用户域内容仅在本机标敏保存且不会注入 Agent 上下文，敏感内容不能写入共享域；
检测服务异常时写入会明确失败，不会静默放行。设备配对、Shell/系统工具和升级
分别要求明确确认或系统授权。离线时记忆服务应保持本地可用并明确标识搜索/同步
降级；升级失败不得删除记忆。若 Agent 写入返回 `IDEMPOTENCY_FAILED`，不得反复重试：
先检查 evidence、knowledge、向量及同步日志，再通过
`POST /agent/idempotency/recover` 提交完整原请求、风险确认和恢复原因；授权后只重发
一次完全相同的原请求。当前该恢复能力是管理 API，图形入口仍待补齐。最终版需补齐
每个页面截图、错误码、人机文案和辅助
功能检查，且与最终 release 同版。
