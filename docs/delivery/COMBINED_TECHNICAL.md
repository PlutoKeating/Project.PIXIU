PIXIU·貔貅：面向麒麟OS Agent的去中心化记忆系统设计与实现

作品编号：603821

版本：0.1.12

平台：银河麒麟桌面操作系统 V11


## 安装、编译与首次使用

直接体验产品请按“路径A”安装随附软件包；审核源码并重建安装包请按“路径B”操作。本章依次说明环境要求、安装与编译命令、首次配置和故障处理。终端框中的 $ 和 > 是提示符，输入命令时请省略；反斜杠表示命令续行。

### 环境与依赖

| 项目 | 要求 |
|---|---|
| 原生运行与编译系统 | 银河麒麟桌面操作系统V11，amd64，桌面用户会话和systemd用户服务 |
| Python | 系统python3必须为3.12，Runtime锁文件固定cp312；不能以3.14替换 |
| 系统AI | 安装并启用Embedding、Vector Engine与麒灵模型服务，在系统AI模块管理中完成授权 |
| 网络 | 首次下载系统软件包、Python wheels及使用云模型时联网；已有本地记忆可离线读写 |
| 权限 | 普通桌面用户运行软件，sudo只用于安装依赖与DEB以及构建隔离 |
| 构建工具 | CMake、Ninja、g++、pkg-config、patch、tar、Python开发头文件、Qt5与KylinSDK开发包 |

检查系统与解释器：

~~~bash
cat /etc/os-release
dpkg --print-architecture
python3 --version
~~~

原生安装和编译要求银河麒麟 V11、amd64 架构和 Python 3.12。请先核对以上输出，再执行本章命令。Debian 系统的兼容构建步骤见“其他平台：从源码编译安装”。

### 路径A：直接安装使用

作品提交包的“源代码”目录提供以下 x64 安装包和校验文件：

1. pixiu_0.1.12-1_amd64.deb
2. pixiu_0.1.12-1_amd64.deb.sha256

在“源代码”目录打开终端，依次执行：

~~~bash
sha256sum -c pixiu_0.1.12-1_amd64.deb.sha256
sudo apt update
sudo apt install ./pixiu_0.1.12-1_amd64.deb
pixiu
~~~

校验显示 OK 后继续安装，安装完成后运行 pixiu 打开主窗口。SHA-256 摘要用于核对安装文件完整性；软件内更新还会验证 Ed25519 签名。需要从源码重建安装包时，按“路径B”操作。

安装包包含桌面程序、记忆服务、Agent Runtime、文档解码组件和 Python 依赖。原生 SDK 运行库由 V11 系统软件源提供。APT 如提示缺少依赖，请先配置官方软件源和 AI 模块，再重新安装。

#### 首次模型设置

在PIXIU“设置”的模型页面选择麒麟系统模型。先在系统“AI模块管理”中完成模型授权，然后发送一句普通问候，确认可以收到回答。使用其他支持的模型服务时，在同一设置页填写该服务的API地址、模型与密钥并测试连接。图片和扫描PDF还要求所选模型支持图像输入。

以当前桌面用户运行 pixiu。服务状态应显示版本 0.1.12、记忆服务就绪，以及系统 Embedding 和 Vector Engine 可用。

#### 五分钟操作验证

1. 新建会话，输入“请记住：九月家庭电费210元、水费68.50元、燃气费156元”。
2. 等待助手确认保存后，新建另一个会话，询问“九月水电燃气共花了多少钱，请列明细并给出来源”。应得到434.50元，并可点击来源核对记录。
3. 在“设置 → 采集与隐私”添加一个资料目录，启用自动采集和目录文件变化并保存设置。把一份包含日期、地点、预算的TXT活动通知直接放入该目录，等待后台处理完成。
4. 新会话询问通知内容；再放入改期通知。打开待审批计划，核对新旧内容并批准，随后查询应使用更新后的安排。
5. 跨设备验证时，在另一台 V11 电脑安装 PIXIU。两端在设备页完成配对，选择同一共享空间。将一条约定保存到该空间后，在另一端新会话中查询并核对来源。目录自动整理的资料默认保存在本机私人范围；跨设备使用需要明确设置共享内容和空间。

### 路径B：由最小源码包编译

源码包包含固定版本的宿主、Runtime、PIXIU 补丁、系统 SDK 头文件、许可证和构建配置。SOURCE-MANIFEST.json 记录版本、上游提交和文件摘要，构建脚本可直接读取。文档解码组件 Kreuzberg 按依赖锁安装预编译包。

#### 1. 解压与核对

把源代码目录中的PIXIU源代码.tar.gz放到一个空工作目录，在该目录执行：

~~~bash
tar -xzf 'PIXIU源代码.tar.gz'
cd PIXIU
python3 verify-source.py
~~~

确认所有源码摘要核对通过后，在解压得到的 PIXIU 目录中执行后续命令。每次复现使用全新解压目录，避免旧构建结果影响检查。

#### 2. 准备系统软件

~~~bash
sudo bash build/release/scripts/provision-target.sh \
  kylin-v11-native-x86_64 --with-build-deps
sudo apt install patch tar gzip file util-linux sudo
python3 -m venv /tmp/pixiu-python-check
/tmp/pixiu-python-check/bin/python --version
~~~

预置脚本从V11官方软件源安装Qt5、WebEngine、WebSockets、Multimedia、pybind11以及KylinSDK开发和运行库。应无“找不到软件包”或未满足依赖的错误。Python检查必须输出3.12。

原生开发包包括 libkylin-coreai-embedding-dev、libkysdk-vector-engine-client-dev、libkysdk-genai-nlp-dev，以及快捷键、通知、Qt 扩展和 Wayland 适配包。预置脚本按 build/release/profiles/kylin-v11-native-x86_64.env 安装完整依赖。

#### 3. 构建宿主与Runtime

~~~bash
sudo -v
export PIXIU_KYSDK=ON
export CMAKE_BUILD_PARALLEL_LEVEL=2
bash build/release/scripts/prepare-agent-supply-chain.sh
~~~

脚本先在隔离网络中编译桌面宿主，再联网下载锁定版本的构建工具和 Runtime 依赖，最后执行离线安装验证。sudo 用于建立网络隔离环境，实际编译以当前普通用户执行。

末尾检查报告显示 ready=true 表示本步骤成功。构建日志、宿主程序、Runtime 依赖包和许可证记录写入 build/release/evidence/agent-supply-chain/，可用于排查构建失败。

#### 4. 生成完整安装包

~~~bash
export PIXIU_PROFILE=kylin-v11-native-x86_64
export PIXIU_KYSDK=ON
export PIXIU_INSTALL_STRICT=1
export PIXIU_PYTHON=python3
export PIXIU_PYTHON_VERSION=312
export PIXIU_SKIP_TESTS=1
make -C build/release build-deb
~~~

最小源码包保留产品构建需要的文件，Runtime 依赖按版本和文件摘要锁定。

PIXIU_SKIP_TESTS=1 用于跳过源码包未附带的前端回归测试工程。上一步已完成宿主编译和启动检查，本步骤继续检查组件版本、构建来源、原生扩展和依赖。

成功后，build/release/out/pixiu_0.1.12-1_amd64.deb 应为非空文件，构建脚本正常退出。该文件是本地重建产物，发布签名和文件摘要以正式发布包为准。

~~~bash
dpkg-deb --info build/release/out/pixiu_0.1.12-1_amd64.deb
sudo apt install ./build/release/out/pixiu_0.1.12-1_amd64.deb
pixiu
~~~

安装完成后，按“路径A”完成首次模型设置和操作验证。

### 其他平台：从源码编译安装

随附 DEB 适用于银河麒麟 V11 x64。其他平台请解压 PIXIU源代码.tar.gz，在目标系统上配置依赖、编译并安装。

Debian 系 x64 环境需要 Python 3.12，可从 generic-ubuntu 构建配置开始适配。预置依赖时使用该配置；准备构建环境前设置 PIXIU_KYSDK=OFF；生成安装包时设置 PIXIU_PROFILE=generic-ubuntu 和 PIXIU_INSTALL_STRICT=0。其余步骤按“路径B”执行，并核对目标发行版的软件包名称。此配置使用可移植实现。

ARM64 等架构需要在目标机编译宿主，按目标 CPU 和 Python 接口版本重建 Runtime 依赖及哈希锁，再添加 build/release/profiles 构建配置并调整 amd64 校验。完成依赖检查、打包和安装验证后，才能确认该架构可用。目前已验证的整包平台为 V11 amd64。

### 故障定位与恢复

| 现象 | 处理方法 |
|---|---|
| Python版本不是3.12 | 使用V11提供的3.12解释器，不修改哈希锁冒充其他ABI |
| 找不到KylinSDK包或库 | 检查V11官方源、AI模块及开发包，重新预置依赖；不要关闭原生检查 |
| Runtime wheel与锁文件不一致 | 停止打包，核对源码摘要、Python3.12、amd64与依赖下载；不要手工改锁 |
| 已存在供应链evidence目录 | 保留日志后换一个全新解压目录重建，不混用旧结果 |
| sudo -n或unshare权限失败 | 当前终端执行sudo -v，使用允许网络命名空间的本机V11环境 |
| 记忆服务未就绪 | 执行下方服务与日志命令，检查系统AI组件和当前用户会话 |
| 会话不能生成回答 | 检查模型授权、地址、密钥和网络；记忆就绪不等于模型连接正常 |
| 目录文件未处理 | 确认目录授权已保存、自动采集开启，文件为直接子文件且不超过30MiB |
| 配对后查不到记录 | 确认两端在线、同一共享范围，记录确实写入共享空间 |

~~~bash
systemctl --user status pixiu-backend.service
journalctl --user -u pixiu-backend.service -n 50 --no-pager
systemctl --user restart pixiu-backend.service
~~~

软件更新在设置中完成。配置、记忆与设备身份位于当前用户目录，升级保留数据。卸载程序使用sudo apt remove pixiu；删除用户数据是另一个操作，卸载前先保留需要的资料。


## 软件架构与实现方案

### 作品概述

PIXIU 帮助用户保存资料、在新会话中找回知识，并在可信设备间共享记忆。用户授权目录后，后台整理功能 Dreaming 读取文件、联系已有记忆并形成整理结果；助手随后按任务需要检索这些知识。

产品提供“自动记忆，持续整合”和“记忆共享，分布互连”两项核心功能。用户可以在同一桌面窗口查看整理进度、核对回答来源、审批更正计划和管理共享范围。

系统接收对话、工具结果、用户行为、手动配置和文档。文本与 Office 资料由包内组件解码；图片及扫描 PDF 由具备多模态能力的当前模型处理。OCR 用于敏感内容定位与标注。

### 解决的问题

跨会话和跨设备工作需要保留任务经验。例如，用户换一台电脑整理家庭账单时，需要找到原来的支出清单、沿用输出偏好，并确认金额来自哪条记录。

PIXIU 分别保存原始证据、知识、偏好和冲突记录。每条记录带有来源、使用范围、版本和敏感程度，便于检索、更新和追溯。

### 总体架构

用户在一个 PIXIU 主窗口中完成会话、记忆管理、设备管理和设置。桌面端基于 openKylin KylinAgent，agent-runtime 负责规划任务、调用工具和请求用户审批。

MemoryProvider 是助手访问 PIXIU 记忆服务的适配接口。它通过公共 API 发送读写请求，后端完成数据接入、偏好提取、知识管理、检索、同步和遗忘。

后端按职责组织模块：记忆引擎处理接入、偏好、知识和安全；基础服务管理存储、检索、记忆流转及评测；同步模块负责设备间的更新；平台适配层调用系统 SDK。

### 记忆写入

系统先校验输入格式、整理字段、评估质量并检查敏感信息，再保存原始证据（evidence）。随后提取知识和偏好，建立实体关系及检索索引，并处理与已有知识的冲突。

助手保存的记忆带有会话、任务、轮次、工具调用、审批和时间信息。适配层先把待发送记录写入本地队列，连接恢复后继续发送。后端记录请求的处理结果，重复请求直接返回已有结果，避免重复写入。

### 自动记忆与持续整合

用户在“采集与隐私”中选择资料目录并开启自动采集。目录中的直接子文件新增、修改或移入后，服务等待文件写入稳定，再把资料交给后台整理流程。每个文件独立处理，目录授权可以随时调整。

Dreaming 逐块阅读已授权文档，并检索相关旧记忆。它根据新资料生成新增、更正或合并方案，再把来源、处理进度和结果显示给用户。用户以后可直接在会话中查询保存的知识。

| 步骤 | 系统的工作 | 用户得到的结果 |
|---|---|---|
| 发现资料 | 接收授权目录中的文件变化，等待文件稳定 | 日常资料自动进入整理流程 |
| 阅读文档 | 解码正文、表格、工作表、幻灯片和图片，保留位置与版本 | 后续回答可回到具体资料内容 |
| 联系旧知识 | 检索相关记录，阅读准备更新或合并的原内容 | 新资料与已保存的知识联系起来 |
| 形成方案 | 新建私人记忆；更正和合并形成待审批方案 | 新知识自动保存，既有知识的调整可先对照 |
| 执行与报告 | 用户批准后按读取时的版本更新，报告处理数量和保存结果 | 主窗口显示进度、待办和完成结果 |

更正与合并计划会持久保存。审批界面展示原记录、建议内容和依据；用户批准后，系统保存新版本并更新检索索引。合并时保留各条原记录的来源，把整理后的内容用于后续查询，原记录转入历史状态。

后台整理使用当前聊天模型。文本、PDF 与 Office 资料通过包内文档组件解码；图片和扫描页面在当前模型具有多模态能力时交给模型理解。模型按内容块分批处理，任务记录实际阅读数量、保存数量与后续处理项。目录文件大小上限为 30 MiB，目录监视覆盖所选目录的直接子文件。

资料读取、记忆检索、方案提交和执行通过限定接口完成。每次读取与保存都会核对目录授权、文档版本和来源；后台整理创建的记忆保存在本机私人采集范围。需要跨设备使用时，用户明确选择共享内容和共享空间。

例如，用户将活动安排保存到授权目录，助手整理时间、地点、预算和操作流程。收到改期通知后，Dreaming 对照原记录提出更正。用户批准后，再次查询会得到更新后的安排和来源。

### 记忆检索

系统通过关键词、语义向量和实体关系三个通道查找知识。关键词通道按 BM25 方法计算词语匹配程度；语义通道查找含义相近的文本；关系通道从商户、类别等实体找到关联记录。

系统采用倒数排名融合方法 RRF 合并三个通道的候选顺序，再按授权范围和时间条件筛选。对家庭支出等结构化记录，后端按查询条件汇总明细，并返回知识与原始资料的引用。

例如，查询“望远镜、器材预算”时，关键词通道匹配词语，语义通道寻找相关活动资料，关系通道查找相连的实体。每个通道按 1 / (60 + 排名) 计分，排名从 1 开始。同一条知识在多个通道中排名靠前时，累计分数更高。

| 处理环节 | 主要依据 | 可核对的结果 |
|---|---|---|
| 候选查找 | 关键词、语义向量、实体关系 | 各通道的相关知识列表 |
| 合并排序 | 各通道中的排名，常数 60 | 同一条知识的综合顺序 |
| 范围与时间筛选 | 用户授权、查询条件 | 本次可使用的知识 |
| 来源组装 | 知识与原始证据关联 | 回答引用及原文入口 |

检索和金额计算由后端执行。银河麒麟 V11 使用系统 Embedding 接口生成文本向量，并通过 Vector Engine SDK 保存、搜索和删除向量。

### 偏好与知识

偏好描述用户希望助手如何工作，包括操作习惯、输出风格和安全策略。系统保存偏好值、置信度和版本历史，供后续任务使用。知识记录事实、工作流程、案例和模板，并关联原始证据。

知识编辑使用版本检查：提交时核对读取版本，已有更新时保留用户输入，并引导用户读取最新内容后继续编辑。冲突页面显示新旧内容、处理方式和时间，便于追查变化原因。

### 精准遗忘

用户用自然语言描述要遗忘的内容，界面先列出目标和相关记录数量。用户确认后，系统将目标知识标为已遗忘并移除向量。原始证据、关系和全文索引中的部分数据仍会保留。

每次预览生成一次性确认凭证，绑定目标及其版本。凭证过期或目标发生变化时，用户需要重新预览。共享知识还会生成删除记录（墓碑），用于向可信设备传播删除状态。

### 可信设备间的记忆共享

每台设备保存本地副本，离线时仍可读取和写入。设备通过交换配对令牌建立信任；共享记录进入带签名的操作日志，私人记录保存在本机。系统分别使用 `shared:*` 和 `user:*` 标识这两种使用范围。

系统根据版本关系合并同一条知识的更新，这一机制称为 CRDT。在线设备通过 Gossip 协议传递新操作；离线设备重连后交换摘要并补齐缺失操作。设备使用双向证书验证身份，并通过加密连接传输数据。

用户先完成设备配对，再为助手选择可读取的共享空间以及新记忆的保存位置。读取与保存分别设置：助手可以同时使用授权的个人资料和家庭共享资料，并把新内容存入用户选择的位置。目录自动整理的私人资料由用户选择后用于协作。

在家庭场景中，书房保存“周六上午九点整理书房、书籍按主题分类”的共享约定，客厅设备上的助手直接找回时间、分类方式和来源。办公场景中，同一机制用于交接步骤、会议安排和资料更新。

连接中断期间，用户仍可读写本地记忆；连接恢复后，设备交换更新并取得一致记录。助手生成自然语言回答时仍需所配置的模型服务可用。

副本层根据版本关系和固定的并发处理规则统一记录。业务层比较知识含义，处理事实矛盾；需要人工判断时，冲突页面显示候选内容和来源，由用户作出选择。

### 记忆流转

短期记忆保存当前任务上下文，中期记忆保存会话或项目状态，长期记忆保存可重复使用的事实、偏好和工作经验。

每轮任务开始前，MemoryProvider 按内容长度上限读取相关长期记忆。轮次结束后，它保存对话和工具结果；会话压缩、切换或结束时保存阶段状态。助手通过记忆工具查询和更新内容，用户在界面确认遗忘操作。

### 安全与隐私

系统在保存资料前检测身份证号、银行卡号和手机号等敏感信息。检测结果决定资料的保存范围和使用权限，敏感记录限于本机受控范围，并从助手检索上下文中排除。

设备配对、风险工具、遗忘和升级分别请求用户确认。模型密钥由 Runtime 的认证功能保存，用户通过设置界面配置模型服务。

### 平台适配

银河麒麟 V11 构建启用桌面 KylinSDK、Embedding SDK 和 Vector Engine SDK。启动检查确认依赖可用后，后端才进入就绪状态。Debian 兼容构建使用可移植实现，验证结果注明实际运行环境。

一个 `.deb` 包含桌面程序、内嵌管理界面、后端、MemoryProvider、Runtime 离线依赖、许可证和版本清单。后端在当前桌面用户的 systemd 会话中运行，以访问该用户的系统 AI 服务。

### 自有实现与上游组件

PIXIU 实现记忆引擎、混合检索、记忆流转、分布式同步、MemoryProvider、系统 SDK 适配、管理界面和评测发布工具。KylinAgent 与 agent-runtime 提供会话、规划、工具和审批功能，各上游组件随包记录版本、来源和许可证。

### 应用价值

用户可以在新任务中调用过去的知识和工具结果，减少重复录入；通过来源和版本记录核对内容；在可信设备之间继续工作。家庭账单检索和跨设备工作流是两组具体应用，操作过程见应用案例。

## 记忆流转与数据保护

PIXIU 按使用时间和用途保存三层记忆。任务进行时使用当前上下文，任务结束后保留有用状态，经过处理的知识和偏好可供以后使用。

### 三层记忆

| 层级 | 保存内容 | 主要用途 |
|---|---|---|
| 短期 | 当前消息、计划和工具上下文 | 继续当前任务 |
| 中期 | 会话摘要、项目状态和中间结果 | 压缩上下文、切换和恢复会话 |
| 长期 | 偏好、事实、工作流、案例和模板 | 在后续任务中重复使用 |

### 保存记忆

系统校验对话或工具结果的来源和质量，检查敏感信息，然后保存原始证据。记忆引擎从证据中提取知识和偏好，处理冲突，再建立关键词、向量和关系图索引。

适配层的 sync_turn 接口保存一轮对话，工具结果同时保留调用、审批和时间信息。待发送记录进入本地持久化队列，连接恢复后继续处理。会话压缩、切换或结束时，系统保存阶段状态。

### 读取记忆

每轮任务开始前，适配层通过 /agent/context 请求相关长期记忆。后端按问题、会话、授权范围、时间和内容长度筛选结果，并排除敏感记录。

返回内容包含更新时间、冲突状态以及知识和原始证据的引用。助手将这些内容作为任务参考，系统指令和权限规则继续约束工具操作。

### 转为长期知识与清理

中期内容经过质量和敏感度等检查后，可转为长期知识，并关联原始证据。短期和中期记录按有效期清理；长期内容通过编辑或遗忘操作更新。冲突旧版用于追查处理过程。

### 在设备间传递

私人记忆保存在本机，共享记忆进入带签名的操作日志。系统用 CRDT 合并并发版本，通过 Gossip 向在线设备传递操作，并在重连后比较记录、补齐遗漏。

遗忘操作产生删除记录（墓碑）。同步合并时，该记录阻止较旧的内容重新变为可见；其他有效节点全部确认后，系统才回收墓碑载荷。双端候选包测试已验证遗忘传播，双方删除记录摘要一致。



![0.1.12：记忆保留活动原始资料](assets/operations/03-current-workflows/directory-source.png)

0.1.12：记忆保留活动原始资料。

### 保护用户数据

系统在写入前检测敏感信息，在检索和同步时检查使用范围。敏感内容限于本机，助手及受委派任务只取得权限允许的参考内容。

遗忘页面先显示目标和相关记录数量，用户核对后确认执行。系统隐藏知识并移除向量，原始证据和部分关联数据仍会保留。

### 测试数据集与标注

评测使用自建合成数据集 pixiu-family-expense-v1，内容根据赛题家庭支出场景生成。数据集包括 50 组账单检索、15 组偏好和 25 组冲突用例；每组检索重复执行 20 次，共记录 1000 次耗时。已有量化结果来自 Debian 可移植环境。

50 组账单各含电费、水费、燃气费和干扰类别，覆盖月份变化、中文表述和 utilities 查询。每条查询含唯一单据编号，并给定月份与共享范围；标准答案标注知识编号、证据编号和金额合计。

15 组偏好用例覆盖操作习惯、输出风格和安全策略，每类 5 组。25 组冲突用例中，20 组预期采用新记录，3 组预期合并，2 组预期交由用户处理。数据与标准答案按生成规则固定，并通过摘要核对版本。

### 量化评测方法与结果

| 指标 | 实测结果 | 目标 |
|---|---:|---:|
| 检索召回率 | 100% | ≥85% |
| 偏好准确率 | 100%（15/15） | ≥85% |
| 冲突处理正确率 | 96%（24/25） | ≥88% |
| 检索 P95 延迟 | 115 ms | ≤500 ms |

检索召回率按每组返回知识与标准知识集合的交集占比计算，再取 50 组平均值。偏好准确率要求返回标签集合与标准集合完全一致；冲突正确率要求处理方式与预期一致。将 1000 次检索耗时升序排列，第 950 个值为 P95，已有记录为 115.151 ms。

已有记录中的 Top-1、Top-3 和 Top-5 召回率均为 100%。金额核对按用例规定的 0.01 元容差执行，来源核对要求包含预期证据集合。复核时同时保存失败样本和原始返回结果，便于判断问题出在检索、金额计算还是来源关联。

### 对比实验设计

对比实验设置无长期记忆、单设备记忆和分布式记忆三组。三组使用相同的 V11 软件版本、模型配置、任务顺序和输入资料，每次试验从独立的空会话与测试库开始。组间仅改变记忆配置，以观察记忆保存和设备共享对任务结果的影响。

任务集采用 30 组虚构资料及唯一标记。先在写入设备交付资料，再在新会话中查询，并在另一台设备重复查询。无长期记忆组保留当前会话能力；单设备组启用本机长期记忆；分布式组增加可信设备配对和授权共享。查询时只提供资料主题，让助手找回原先保存的标记。

每组统计跨会话答对率、跨设备答对率、来源一致率和回答耗时。答对要求返回标准标记，来源一致要求知识与证据对应。按相同任务逐组比较结果，并记录失败原因。实验记录按组保存，结果表逐项列出样本数、成功数、耗时和运行环境。

### 量化评测实施方案

复测先记录操作系统、CPU、内存、PIXIU 版本、SDK 状态和模型配置，再将固定数据导入独立测试库。逐组执行检索、偏好和冲突用例，保存输入编号、预期结果、实际结果、耗时和错误状态。各组按相同顺序执行，发生异常的样本计入失败记录。

检索耗时从发出检索请求开始，到取得完整结果结束，包含向量生成、检索、排序和结果组装。模型生成整段回答的耗时另行统计。按每组 20 次得到 1000 个样本，计算中位数和 P95；同时记录首次查询及缓存状态，便于解释冷热差异。

完成后按相同公式计算四项指标，对照准确率和召回率至少 85%、冲突正确率至少 88%、检索 P95 不超过 500 ms 的目标。报告保存数据集摘要和逐样本明细。V11 复测须确认指定 Embedding 与 Vector Engine 均实际参与处理。

### 指标分析与适用范围

在已有 Debian 记录中，检索召回率和偏好准确率均为 100%，比 85% 目标高 15 个百分点。冲突正确率为 24/25，即 96%，比 88% 目标高 8 个百分点。检索 P95 为 115.151 ms，低于 500 ms 目标。

以上指标对应带唯一单据编号、月份和共享范围的合成查询。检索结果反映指定账单的定位效果，偏好结果反映 15 组标准标签匹配情况，冲突结果反映 25 组预设处理方式的判断情况。评价其他任务时，采用相应数据和相同统计口径复测。

三台 V11 虚拟机在重连后约 30.5 秒取得一致记录。验证同时核对正文、版本、来源和同步状态，说明该次断连与并发更新后各端恢复到相同结果。记录测试拓扑、网络条件和数据量，可供同条件复核。

### 验证结论与复核

0.1.12 的 V11 记录支持单包安装、指定 SDK 调用、记忆读写、后台更正审批和三端重连等功能结论。Debian 量化记录对应本章所列数据集和统计口径。复核时以软件版本、安装包摘要、运行环境和逐样本结果关联各项结论。

### 用户会话架构

系统 AI 服务按桌面用户分开管理连接。PIXIU 后端因此运行在当前用户的 systemd 会话中，使系统向量服务、Agent 运行时和本地记忆都使用同一用户身份。

服务启动时验证运行进程所属用户、本机服务身份、产品版本和数据库状态，确保各组件连接到当前用户的记忆服务。

### Embedding SDK

系统通过 Kylin coreai/embedding 接口把文本转换为 gte-base 模型的 768 维向量。启动时先检查模型、AI 服务、客户端库和 SDK 调用，全部就绪后开始处理业务。

### Vector Engine SDK

向量库通过 ConnectParam(appId) 建立本地应用连接，再用 LoadDBFile 加载该应用的数据库。系统随后执行集合创建、向量写入、搜索和删除，退出时清理资源并断开连接。

启动预检在首条业务写入前验证数据库生命周期。产品接口验证记忆写入、召回、遗忘及检索结果随遗忘更新。

### KylinSDK 与界面

`KYSDK=ON` 构建启用系统快捷键、通知和 Qt 扩展适配。界面按浅色和深色主题设置文字、背景及状态颜色，消息区保持居中阅读宽度，长会话标题省略显示，键盘焦点和操作状态清晰可见。

Debian 兼容构建使用标准 Qt 快捷键和系统托盘通知，用于验证基本桌面功能。麒麟 SDK 功能在 V11 环境单独测试。

### 安装与升级

单一 .deb 包含桌面宿主、管理界面、后端、记忆适配、Runtime 离线依赖和原生扩展。包内同时提供软件物料清单 SBOM 与版权许可证说明 NOTICE，便于核对组件来源。

安装前置脚本校验 V11 与架构；服务启动再次校验双 SDK；用户首次启动校验 Agent 与 Runtime。各阶段检查通过后继续执行。

图形升级先验证安装包摘要和签名，安装后检查软件版本、数据库结构、记忆适配接口和服务状态。检查失败时，自动恢复机制还原原有安装包、配置、数据和服务。
