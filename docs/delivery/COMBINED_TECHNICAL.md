# PIXIU 技术方案

版本：0.1.12

平台：银河麒麟桌面操作系统 V11


## PIXIU 技术方案

### 作品概述

PIXIU 将资料整理与可信设备协作连成一条完整的记忆链路：授权目录接收日常文件，Dreaming 在后台理解和整理资料，助手在新会话中按需找回知识，可信设备通过共享空间继续使用这些经验。

作品的两项核心亮点是**目录监控与 Dreaming 自动整理**、**去中心化多设备记忆协作**。前者帮助用户持续积累有来源的知识，后者让知识跨设备复用。用户在同一个桌面窗口中查看整理进度、核对回答来源、审批更正计划和管理共享范围。

系统接收对话、工具结果、用户行为、手动配置和文档。文本与 Office 资料由包内组件解码；图片及扫描 PDF 由具备多模态能力的当前模型处理。OCR 用于敏感内容定位与标注。

### 解决的问题

跨会话和跨设备工作需要保留任务经验。例如，用户换一台电脑整理家庭账单时，需要找到原来的支出清单、沿用输出偏好，并确认金额来自哪条记录。

PIXIU 分别保存原始证据、知识、偏好和冲突记录。每条记录带有来源、使用范围、版本和敏感程度，便于检索、更新和追溯。

### 总体架构

用户在一个 PIXIU 主窗口中完成会话、记忆管理、设备管理和设置。桌面端基于 openKylin KylinAgent，agent-runtime 负责规划任务、调用工具和请求用户审批。

PIXIU 通过 MemoryProvider 接口为助手提供记忆读写能力。该适配层调用公共 API；后端负责数据接入、偏好提取、知识管理、检索、同步和遗忘。

后端按职责组织模块：记忆引擎处理接入、偏好、知识和安全；基础服务管理存储、检索、记忆流转及评测；同步模块负责设备间的更新；平台适配层调用系统 SDK。

### 记忆写入

系统先校验输入格式、整理字段、评估质量并检查敏感信息，再保存原始证据（evidence）。随后提取知识和偏好，建立实体关系及检索索引，并处理与已有知识的冲突。

助手产生的记忆保留会话、任务、轮次、工具调用、审批和时间信息。后端保存写入请求的处理结果，重复请求可复用已完成的结果。Provider 将待发送记录保存在本地队列中，连接恢复后继续发送。

### 核心亮点一：目录监控与 Dreaming

用户在“采集与隐私”中选择资料目录并开启自动采集。目录中的直接子文件新增、修改或移入后，服务等待文件写入稳定，再把资料交给后台整理流程。每个文件独立处理，目录授权可以随时调整。

Dreaming 是围绕已授权资料运行的后台助手。它逐块阅读文档，检索已有记忆，判断资料提供了新的知识、更新了既有事实，还是适合与已有记录合并。系统将整理结果、来源和进度呈现给用户，让日常保存文件自然衔接到以后可用的知识。

| 步骤 | 系统的工作 | 用户得到的结果 |
|---|---|---|
| 发现资料 | 接收授权目录中的文件变化，等待文件稳定 | 日常资料自动进入整理流程 |
| 阅读文档 | 解码正文、表格、工作表、幻灯片和图片，保留位置与版本 | 后续回答可回到具体资料内容 |
| 联系旧知识 | 检索相关记录，阅读准备更新或合并的原内容 | 新资料与已保存的知识联系起来 |
| 形成方案 | 新建私人记忆；更正和合并形成待审批方案 | 新知识自动保存，既有知识的调整可先对照 |
| 执行与报告 | 用户批准后按读取时的版本更新，报告处理数量和保存结果 | 主窗口显示进度、待办和完成结果 |

更正与合并计划会持久保存。审批界面展示原记录、建议内容和依据；用户批准后，系统保存新版本并更新检索索引。合并时保留各条原记录的来源，把整理后的内容用于后续查询，原记录转入历史状态。

后台整理使用当前聊天模型。文本、PDF 与 Office 资料通过包内文档组件解码；图片和扫描页面在当前模型具有多模态能力时交给模型理解。模型按内容块分批处理，任务记录实际阅读数量、保存数量与后续处理项。目录文件大小上限为 30 MiB，目录监视覆盖所选目录的直接子文件。

资料读取、记忆检索、方案提交和执行通过限定接口完成。每次读取与保存都会核对目录授权、文档版本和来源；后台整理创建的记忆保存在本机私人采集范围。需要跨设备使用时，用户明确选择共享内容和共享空间。

例如，将读书会资料保存到授权目录，助手整理时间、地点、预算和图书归还流程。收到更新通知后，Dreaming 对照原记录提出更正，用户批准；随后在新会话中询问活动安排，助手使用更新后的知识并提供来源。

### 记忆检索

系统同时按关键词、语义相似度和实体关系查找候选内容。关键词通道使用 BM25 评分；语义通道比较文本向量；关系图通道沿实体关系查找相关知识。

系统用 RRF 方法合并三个通道的排名，再按使用范围和时间筛选结果。对于家庭支出等结构化数据，系统还能汇总金额。结果附带知识和原始证据的引用，用户可据此核对来源。

例如，用户输入“望远镜、器材预算”，关键词通道寻找相应词语，语义通道寻找表达相关的活动资料，关系通道联系资料中的实体。每个通道先排出候选顺序，再把同一条知识的排名贡献相加。当前实现采用 `1 / (60 + 排名)`，排名从 1 开始；同一条知识在多个通道靠前时，会得到更高的合并分数。系统同时核对授权范围和时间条件，再组装带来源的结果。

| 处理环节 | 主要依据 | 可核对的结果 |
|---|---|---|
| 候选查找 | 关键词、语义向量、实体关系 | 各通道的相关知识列表 |
| 合并排序 | 各通道中的排名，常数 60 | 同一条知识的综合顺序 |
| 范围与时间筛选 | 用户授权、查询条件 | 本次可使用的知识 |
| 来源组装 | 知识与原始证据关联 | 回答引用及原文入口 |

检索和金额计算由后端执行。银河麒麟 V11 使用系统 Embedding 接口生成文本向量，并通过 Vector Engine SDK 保存、搜索和删除向量。

### 偏好与知识

偏好包括操作习惯、输出风格和安全策略。系统保存提取结果、置信度和版本历史，供后续任务使用。知识包括事实、工作流、案例和模板，并关联支持它们的原始证据。

知识编辑使用版本检查：提交时核对读取版本，已有更新时保留用户输入，并引导用户读取最新内容后继续编辑。冲突页面显示新旧内容、处理方式和时间，便于追查变化原因。

### 精准遗忘

用户用自然语言描述要遗忘的内容，界面先列出目标和相关记录数量。用户确认后，系统将目标知识标为已遗忘并移除向量。原始证据、关系和全文索引中的部分数据仍会保留。

每次预览生成一次性确认凭证，绑定目标及其版本。凭证过期或目标发生变化时，用户需要重新预览。共享知识还会生成删除记录（墓碑），用于向可信设备传播删除状态。

### 核心亮点二：去中心化多设备记忆协作

每台设备保存本地副本，离线时仍可读取和写入。设备通过交换配对令牌建立信任；共享记录进入带签名的操作日志，私人记录保存在本机。系统分别使用 `shared:*` 和 `user:*` 标识这两种使用范围。

CRDT 根据版本信息合并同一条知识的并发更新。Gossip 将新操作传给在线设备；反熵对账在设备重连后比较记录并补齐遗漏。设备间通过双向证书验证身份，使用加密连接传输数据。

用户先完成设备配对，再为助手选择可读取的共享空间以及新记忆的保存位置。读取与保存分别设置：助手可以同时使用授权的个人资料和家庭共享资料，并把新内容存入用户选择的位置。目录自动整理的私人资料由用户选择后用于协作。

在家庭场景中，书房保存“周六上午九点整理书房、书籍按主题分类”的共享约定，客厅设备上的助手直接找回时间、分类方式和来源。办公场景中，同一机制用于交接步骤、会议安排和资料更新。

每台设备保存本地副本。连接中断期间，本机记忆读写继续工作；连接恢复后，设备交换更新并逐步取得一致记录。这里的离线能力指本地记忆保存与检索，助手生成回答使用所配置的模型服务。

同条记录在两端同时修改时，系统根据版本关系和确定性规则选择一致结果；涉及事实含义的矛盾由知识冲突处理流程判断。用户可在冲突页面核对候选内容和来源，完成需要人工判断的选择。这样，副本一致性与事实核对各有明确的处理依据。

### 记忆流转

短期记忆保存当前任务上下文，中期记忆保存会话或项目状态，长期记忆保存可重复使用的事实、偏好和工作经验。

每轮任务开始前，MemoryProvider 按内容长度上限读取相关长期记忆。轮次完成后保存对话和工具结果，压缩、切换或结束会话时保存中期状态。助手可以调用记忆工具查询、记录和更新内容；遗忘执行由用户在界面确认。

### 安全与隐私

写入前，系统检查身份证号、银行卡号和手机号等敏感信息。敏感内容保存在本机受控范围，助手按授权使用通过检查的知识。每次写入先完成敏感检查，再保存资料。

设备配对、风险工具、遗忘和升级分别请求用户确认。模型密钥由 Runtime 的认证功能保存，用户通过设置界面配置模型服务。

### 平台适配

银河麒麟 V11 构建启用桌面 KylinSDK、Embedding SDK 和 Vector Engine SDK。启动检查确认依赖可用后，后端才进入就绪状态。Debian 兼容构建使用可移植实现，验证结果注明实际运行环境。

一个 `.deb` 包含桌面程序、内嵌管理界面、后端、MemoryProvider、Runtime 离线依赖、许可证和版本清单。后端在当前桌面用户的 systemd 会话中运行，以访问该用户的系统 AI 服务。

### 实现分工

PIXIU 实现记忆引擎、混合检索、记忆流转、分布式同步、MemoryProvider、系统 SDK 适配、管理界面和评测发布工具。KylinAgent 与 agent-runtime 提供会话、规划、工具和审批功能，各上游组件随包记录版本、来源和许可证。

### 应用价值

用户可以在新任务中调用过去的知识和工具结果，减少重复录入；通过来源和版本记录核对内容；在可信设备之间继续工作。家庭账单检索和跨设备工作流是两组具体应用，操作过程见应用案例。


## PIXIU 部署指南

### 安装环境

银河麒麟桌面操作系统 V11，amd64 架构，Python 3.12。系统 AI 模块提供 Embedding、Vector Engine 和麒灵模型服务。

0.1.12 安装包包含桌面程序、后台服务、Agent Runtime、文档解码组件及所需 Python 依赖。文档处理全程在后台运行，安装包自带解码能力。

### 应用行为采集环境

应用使用时长通过 X11 窗口信息统计。使用这一采集入口时，在系统安装 `x11-utils`，并在“采集与隐私”中开启应用行为统计。银河麒麟 V11 仓库提供该工具；后台服务通过当前桌面会话读取应用和窗口标题，按时间窗口汇总使用时长。

```bash
sudo apt install x11-utils
```

### 下载与安装

从 0.1.12 发布页面下载安装包及对应校验文件。在下载目录执行：

```bash
sha256sum -c pixiu_0.1.12-1_amd64.deb.sha256
sudo apt install ./pixiu_0.1.12-1_amd64.deb
```

正式发布提供 SHA-256 和 Ed25519 签名。应用内更新会自动完成签名校验。

### 启动

从应用菜单打开 PIXIU，或执行：

```bash
pixiu
```

首次启动自动创建当前用户的数据目录，启动后台服务并激活记忆插件。在设置中查看模型连接及服务状态，即可开始会话。



![0.1.12：启动后版本一致，记忆服务和系统 SDK 就绪](assets/operations/03-current-workflows/sdk-version.png)

### 数据与升级

配置、记忆和设备身份保存在当前用户目录。升级会保留这些数据，并在完成后核对版本和服务状态。

正式包测试已通过新装启动、签名升级和自动恢复。升级前后 47 条记忆的完整摘要一致；第三台新装测试机生成了独立设备身份。

### 运行检查

```bash
systemctl --user status pixiu-backend.service
journalctl --user -u pixiu-backend.service -n 50
```

正常启动后，设置页显示服务就绪。麒麟模型授权由系统“AI 模块管理”维护。


## PIXIU 用户手册

适用版本：0.1.12。平台：银河麒麟桌面操作系统 V11。

### 开始使用

安装后从应用菜单打开 PIXIU。主窗口提供“会话、记忆、设备、设置”四个入口；记忆和设置的分类位于左侧。

### 与助手协作

1. 点击“新建会话”，输入目标；需要处理文件时点击“添加附件”。
2. 助手规划工作并报告进度。出现审批请求时，核对计划后批准。
3. 在回答中查看结果，点击来源链接阅读对应原文。

例如：“记住这份采购清单，下次帮我核对金额。”以后在新会话中直接询问清单内容即可。



![0.1.12：助手返回活动日期、地点、预算和来源](assets/operations/03-current-workflows/updated-recall.png)

0.1.12：助手返回活动日期、地点、预算和来源。

### 资料与记忆

在“记忆”中检索资料、阅读来源、查看偏好和简报。需要更正时，可以直接告诉助手新的内容，也可以编辑找到的记忆。

在对话中说明“回答简洁一些”等偏好，助手会保存并在后续任务中使用。偏好页提供当前设置和版本历史。

需要遗忘时，告诉助手具体目标。核对界面列出的内容并确认后，系统隐藏相关知识、清理检索向量，并同步共享记录的遗忘状态。



![0.1.12：点击回答来源，阅读活动原始资料](assets/operations/03-current-workflows/directory-source.png)

0.1.12：点击回答来源，阅读活动原始资料。

### 文件与后台整理

聊天附件支持文本、PDF 和常见 Office 文档。系统自动解码并按内容分块交给助手。图片及扫描 PDF 使用当前模型的多模态能力，适用状态显示在设置页。

#### 授权目录，让资料自动进入记忆

1. 打开“设置 → 采集与隐私”，点击“添加文件夹”选择用于整理的资料目录。
2. 开启“启用自动采集”和“目录文件变化”，点击“保存设置”。
3. 把资料保存或移入所选目录，也可以编辑其中已有文件。监控覆盖该目录的直接子文件；需要整理子目录时，分别添加对应目录。
4. 主窗口显示后台整理进度。完成后，在采集日志核对文件与保存结果，再到会话中询问资料内容。
5. 点击回答来源，核对资料原文和整理后的知识。

建议先用一份活动安排开始：写明日期、地点、预算和操作流程，保存后询问“读书会什么时候举行，资料预算是多少？”这条路径把日常保存文件与以后查询资料连接起来。

#### Dreaming：后台阅读与整理

Dreaming 会分批阅读授权资料，检索已有知识并形成整理方案。新知识保存在个人资料中；对已有记录的更正和合并会显示审批入口。主窗口根据任务状态显示阅读进度、已保存数量和需要处理的计划。

更正资料时，将更新通知放入授权目录。打开待审批计划，对照原内容、建议结果和依据，点击批准。完成后在新会话中再次查询，核对新的日期、地点或金额。合并计划会集中展示参与整理的原记录与最终内容，批准后来源继续保留。

目录资料大小上限为 30 MiB。文字与 Office 内容由安装包内的文档组件读取，图片和扫描 PDF 使用当前模型的多模态能力。设置页显示当前资料读取能力，任务按实际处理结果报告进度。

采集授权由用户管理。关闭自动采集后，已经保存的记忆继续可用。更改目录列表并保存后，服务按新的目录授权处理后续资料。

## PIXIU 记忆流转说明

PIXIU 按使用时间和用途保存三层记忆。任务进行时使用当前上下文，任务结束后保留有用状态，经过处理的知识和偏好可供以后使用。

### 三层记忆

| 层级 | 保存内容 | 主要用途 |
|---|---|---|
| 短期 | 当前消息、计划和工具上下文 | 继续当前任务 |
| 中期 | 会话摘要、项目状态和中间结果 | 压缩上下文、切换和恢复会话 |
| 长期 | 偏好、事实、工作流、案例和模板 | 在后续任务中重复使用 |

### 保存记忆

系统校验对话或工具结果的来源和质量，检查敏感信息，然后保存原始证据。记忆引擎从证据中提取知识和偏好，处理冲突，再建立关键词、向量和关系图索引。

Provider 的 `sync_turn` 接口保存用户与助手的一轮对话，工具结果保留调用、审批和时间信息。发送记录先进入本地持久化队列，连接恢复后继续处理待办。会话压缩、切换或结束时，系统保存相应的中期状态。

### 读取记忆

每轮任务开始前，Provider 通过 `/agent/context` 请求相关长期记忆。系统按查询、会话、使用范围、时间和长度上限筛选内容，并排除敏感记录。

返回内容包含更新时间、冲突状态以及知识和原始证据的引用。助手将这些内容作为任务参考，系统指令和权限规则继续约束工具操作。

### 转为长期知识与清理

中期内容经过质量和敏感度等检查后，可转为长期知识，并关联原始证据。短期和中期记录按有效期清理；长期内容通过编辑或遗忘操作更新。冲突旧版用于追查处理过程。

### 在设备间传递

私人记忆保存在本机，共享记忆进入带签名的操作日志。系统用 CRDT 合并并发版本，通过 Gossip 向在线设备传递操作，并在重连后比较记录、补齐遗漏。

遗忘操作产生删除记录（墓碑）。同步合并时，该记录阻止较旧的内容重新变为可见；其他有效节点全部确认后，系统才回收墓碑载荷。双端候选包测试已验证遗忘传播，双方删除记录摘要一致。



![0.1.12：记忆保留活动原始资料](assets/operations/03-current-workflows/directory-source.png)

0.1.12：记忆保留活动原始资料。

### 保护用户数据

系统在写入前检测敏感信息，在检索和同步时检查使用范围。敏感内容限于本机，助手及受委派任务只取得权限允许的参考内容。

遗忘页面先显示目标和相关记录数量，用户核对后确认执行。系统隐藏知识并移除向量，原始证据和部分关联数据仍会保留。

### 用户会话架构

系统 AI Runtime 的 Unix socket 按桌面用户 UID 隔离。PIXIU 后端因此运行在当前用户的 systemd 会话中，使 Embedding、Vector Engine、Agent Gateway 和本地数据都处于同一安全边界。

服务启动时验证运行进程所属用户、本机服务身份、产品版本和数据库状态，确保各组件连接到当前用户的记忆服务。

### Embedding SDK

系统通过 Kylin `coreai/embedding` 接口生成 gte-base 768 维文本向量。启动检查确认模型、AI Runtime、客户端库和 SDK 调用就绪后，服务开始工作。

### Vector Engine SDK

产品使用系统 Vector Engine 的 `ConnectParam(appId)` 本地连接，通过 `LoadDBFile` 加载独立应用数据库，并执行集合创建、向量写入、搜索、删除、清理与断开。

启动预检在首条业务写入前验证数据库生命周期。产品接口验证记忆写入、召回、遗忘及检索结果随遗忘更新。

### KylinSDK 与界面

`KYSDK=ON` 构建启用系统快捷键、通知和 Qt 扩展适配。界面按浅色和深色主题设置文字、背景及状态颜色，消息区保持居中阅读宽度，长会话标题省略显示，键盘焦点和操作状态清晰可见。

Debian 兼容构建使用标准 Qt 快捷键和系统托盘通知，用于验证基本桌面功能。麒麟 SDK 功能在 V11 环境单独测试。

## PIXIU 源代码规范与许可证

### 源码结构

| 目录 | 内容 | 归属 |
|------|------|------|
| `frontend/` | 内嵌记忆管理界面与 UKUI 适配 | 团队原创 |
| `backend/engine/` | 接入、偏好、知识、冲突、安全 | 团队原创 |
| `backend/foundation/` | API、存储、检索、流转、同步、评测 | 团队原创 |
| `backend/agent/` | MemoryProvider、文档工具与 Dreaming 后台整理 | 团队原创 |
| `build/release/` | 构建、打包、发布与源码导出 | 团队原创 |
| `backend/platform/` | 初始化、启动、升级与数据迁移 | 团队原创 |
| `tests/acceptance/` | 跨模块用户场景验证及模拟夹具 | 团队原创 |
| `third_party/` | 固定版本的上游与系统 SDK 源码 | 上游依赖 |

### 原创边界

PIXIU 原创成果包括统一记忆模型、多源接入、目录监控、Dreaming 受控文档整理与审批、偏好与知识引擎、三通道混合检索、冲突仲裁、精准遗忘、CRDT/Gossip/反熵同步、Agent 适配、两个系统 SDK 的集成、管理界面和评测发布工具。

KylinAgent 与 agent-runtime 提供通用会话、规划、工具、审批和运行控制。交付材料记录这些上游组件的来源、版本和许可证。

### 主要上游依赖

| 依赖 | 用途 | 许可证 |
|------|------|--------|
| `kylin-agent` | 桌面 Agent 宿主 | AGPL-3.0-only |
| `agent-runtime` | Agent 运行时与 MemoryProvider 接口 | MIT |
| `kylin-coreai-embedding` | 指定文本向量接口 | GPL-3.0-or-later |
| `openpyxl` / `Pillow` | XLSX 图片、公式、批注和图表内容 | MIT / HPND（许可证随 wheel 安装） |
| `kreuzberg` 4.10.3 | 后台 Office/PDF 解码 | MIT（安装包附带本地组件许可证） |
| `libkysdk-vector-engine-client` | 指定系统向量数据库客户端 | Apache-2.0 |

每个上游组件固定 commit，并随源码归档提供许可证、NOTICE、补丁、构建记录和摘要。Runtime 的 Python 依赖以哈希锁定 wheelhouse 离线安装。

### 源码质量规范

- Python 使用类型标注、清晰命名和 pytest；C++/Qt 遵循模块现有风格与 CTest。
- Engine 只通过 Repository 接口访问基础设施；Agent 适配只调用公共 HTTP API。
- 专有 Kylin SDK 位于适配层后，Debian 构建提供明确降级路径。
- 源码归档使用公开配置模板、测试夹具和必要构建文件。
- 一个逻辑变更对应一个本地 Git 提交，版本由根目录 `VERSION` 单一派生。

### 源码交付与复现

`源代码/PIXIU源代码.tar.gz` 包含产品版本对应的前端、后端、Agent 适配、构建配置、测试、技术规范和全部固定版本上游源码。源码清单记录文件摘要、可执行权限和上游提交；保留第三方许可证及版权声明。

解压后先运行包内 `verify-source.py` 核对文件。后端测试使用 `backend/requirements.txt` 与 `backend/foundation/requirements-sync.txt` 的依赖，前端使用 CMake。严格安装包需在银河麒麟 V11 安装官方 SDK 和画像列出的开发依赖，按构建说明执行。依赖清单与源码一起提供，系统软件与 Python wheels 按依赖清单在构建时准备。

Git 工作区通过固定提交核验上游；解压源码通过 SOURCE-MANIFEST.json 核验上游文件、版本及构建时间。先运行 `python3 verify-source.py`，再按 `build/release/README.md` 准备系统与 Python 依赖，使用同一宿主和 Runtime 构建入口。原生安装验证在 V11 进行。

### 软件物料清单

安装包内置 SPDX 2.3 SBOM 与 NOTICE，覆盖宿主、Runtime 和全部 wheel 依赖。发布清单同时记录产品版本、架构、构建画像、API/schema/provider 版本、上游 commit 与 SDK 源码版本。

供应链审计要求宿主产物、对应源码、构建日志、Runtime wheelhouse、锁文件和离线安装日志摘要一致，并扫描认证信息、私钥、令牌和个人路径。
