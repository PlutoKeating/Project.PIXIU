# PIXIU 赛题完整交付主实施计划

> 状态：执行中（2026-09-03）
>
> 目标：交付一个在银河麒麟桌面操作系统 V11 上可一键安装、可在图形界面内
> 一键安全升级、基于完整 OS Agent 运行，并以分布式全连接记忆网络为核心创新的
> 稳定参赛作品。
>
> 权威边界：`OriginProblemDescription.md` 与 `完整赛题要求.pptx` 是共同适用且
> 禁止修改的赛事原件；本计划只负责落实要求，不改写官方原文。

## 1. 完成定义

只有下列条件全部满足，项目才可标记“完整稳定可交付”。任一项未通过时，README、
答辩材料和 Release 均不得宣称赛题验收通过。

1. 最终候选版本在银河麒麟桌面操作系统 V11 安装、启动和卸载通过（H-01）。
2. 生产向量建库、写入、删除和查询真实调用系统 Vector Engine SDK；严格模式缺失
   或不可用时立即失败，portable 结果不得顶替（H-02）。
3. 文本向量化真实调用系统 Embedding SDK；严格模式缺失即失败（H-03）。
4. PIXIU 作为原创 MemoryProvider/适配层接入可用的 openKylin Agent 宿主，完成
   多会话、多轮、规划、工具自主选择、Shell、联网搜索、审批、流式状态与停止恢复。
5. 对话、工具结果、行为和手动配置进入统一记忆管线；记忆可自主召回、价值判断、
   回写、跨会话复用并可精准遗忘。
6. 至少三台设备通过离线写入、并发更新、重连反熵、冲突仲裁、共享遗忘与最终收敛。
7. 单个版本化 `.deb` 可由 V11 图形安装器一键安装；软件 GUI 可完成检查更新、
   独立签名校验、授权升级、迁移、健康检查和失败恢复，且用户数据不丢失。
8. `AcceptanceTestSpecification.md` 中 H、A、F、P、R 项均有同一候选 commit 的
   可复现证据；D-01～D-10 均已生成规定格式并经人工审核。
9. 源码、依赖、许可证、SBOM、包、报告、PPT、视频和证据 manifest 的版本与摘要一致。

## 2. 执行原则

- **实现路线**：执行 ADR-0001；不从零重造 OS Agent，以固定版本的
  `kylin-agent`/`agent-runtime` 为宿主，PIXIU 保持作品主体和记忆创新边界。
- **供应链门**：官方宿主/Runtime 尚未形成 V11 可重建、离线、无认证地址的发行
  组合；按 Proposed ADR-0003 完成前，不得把阶段性宿主探针当作最终单包。
- **模块边界**：A 仅改 `frontend/`；B 仅改 `backend/engine/` 与必要的 core 公共
  契约；C 仅改 `backend/foundation/`；E 仅改 `integrations/kylin_agent/`；跨模块
  装配只在公开 API、core 契约和 DI 组合根发生。
- **测试先行**：每个行为先提交失败测试或在同一小提交中留下清晰红绿证据；先跑
  单测，再跑模块测试，阶段末跑全量回归。
- **证据分层**：portable/Debian、模拟 SDK、V11 真 SDK、单机与多机证据分开保存，
  不以兼容路径冒充赛事门槛。
- **密集同步**：一个可审查逻辑切片一个本地 commit；每次提交后立即推送当前远程
  `main`。不做 force push，不在门禁通过前创建“最终版”标签。
- **文档伴随代码**：每个代码提交同步更新受影响模块架构、任务、API、配置、部署、
  测试报告和本计划状态；官方两份原件始终保持哈希不变。

当前 V11 x86_64 软件源已确认并安装双 SDK、桌面 KylinSDK 及开发包；提交 `ea92b28`
已生成 `KYSDK=ON`/strict amd64 包，包内包含两个 cp312 原生扩展，前端 ctest 38/38。
首次 strict 安装运行确认官方 AI runtime socket 按 UID 隔离，而当前 systemd 后端的
专用系统账户无法访问桌面用户会话 runtime；服务按设计失败关闭，portable 恢复后健康。
因此 W2.6 成为 W1.6/W2.4 的前置项。组件兼容性探针已让官方 demo 和 PIXIU 绑定
通过 runtime 1.3.0 返回 gte-base 768 维非零向量；这不等于最终依赖已可交付。当前仍缺 Agent 宿主/runtime 与 Vector Engine/
Embedding 真服务全链路证据，W1.6/W2.4/W2.5/W2.6 和 H-02/H-03 保持未完成/不通过。
Vector Engine 的独立诊断同时确认新版 user service 正常启动，但 PIXIU 当时强制连接
不存在的 `127.0.0.1:19530`；官方 demo 与头文件证明生产应使用
`ConnectParam(appId)`，相关 Module B/C/发布配置已分层修正；提交 `4011d0d` 的 V11
revision 7 原生重编及固定测试向量 direct lifecycle 已全部通过。该结果不替代产品
API 和 Embedding 闭环。

2026-09-04 的同用户产品探针还揭示：旧组合根只创建 Vector 客户端，未执行官方要求
的 `LoadDBFile`，所以 `/capabilities` 可误报 ready，而 `/memory/write` 返回 local
storage not found。当前源码已加入独立数据库路径、启动装载、单例复用与关机断开，
并以当前 806 项测试回归。提交 `6f6002e` 的 strict revision 8 已重建并通过写入、查询、
遗忘与隐藏检查；正式取证器因目标系统缺少 Agent 宿主/runtime 可执行文件而拒绝出证。

W2.6 的推荐设计已写入
[`ADR-0002`](decisions/0002-run-native-backend-in-user-session.md)：系统级 `.deb`
安装 root-owned 程序，后端作为桌面用户服务与 Agent/双 SDK 同 UID 运行，用户数据迁入
XDG 目录，图形升级拆成用户态停启/健康检查与特权安装两阶段。ADR 批准前不删除旧
system service 或移动数据。

## 6. 风险与停止线

| 风险 | 处理方式 | 停止线 |
|------|----------|--------|
| V11 或 SDK 环境暂不可用 | 继续完成可验证代码、模拟契约和脚本；把真机项保留为未通过 | 不得发布最终版或填写真实 SDK 通过 |
| SDK 主键/删除语义与假设不符 | 以归档头文件、demo 和真机结果为准，调整适配层 | 不得以 SQLite 搜索伪装生产 SDK |
| 上游 Agent API 变动 | 固定 commit、兼容探测、契约测试；必要时新增 ADR | 不得隐式修改 submodule |
| GUI 更新安装失败 | 保留上一包与 schema 备份，健康失败自动恢复 | 未证明恢复前不得开启默认自动更新 |
| 三设备网络不稳定 | 保存故障注入、消息摘要和最终状态，区分超时与不收敛 | 不得用单进程三节点替代最终真机证据 |
| 时间压缩 | 优先 H-01～H-03、完整 Agent、三设备与可安装包 | 不得删除失败结果或降低验收口径 |
