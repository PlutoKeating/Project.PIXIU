# PIXIU 赛题完整交付主实施计划

> 状态：执行中（2026-09-03）
>
> 目标：交付一个在银河麒麟桌面操作系统 V11 上可一键安装、可在图形界面内
> 一键安全升级、基于完整 OS Agent 运行，并以分布式全连接记忆网络为核心创新的
> 稳定参赛作品。
>
> 权威边界：`OriginProblemDescription.md` 与 `完整赛题要求.pptx` 是共同适用且
> 禁止修改的赛事原件；本计划只负责落实要求，不改写官方原文。

## 1. 完成定义

只有下列条件全部满足，项目才可标记“完整稳定可交付”。任一项未通过时，README、
答辩材料和 Release 均不得宣称赛题验收通过。

1. 最终候选版本在银河麒麟桌面操作系统 V11 安装、启动和卸载通过（H-01）。
2. 生产向量建库、写入、删除和查询真实调用系统 Vector Engine SDK；严格模式缺失
   或不可用时立即失败，portable 结果不得顶替（H-02）。
3. 文本向量化真实调用系统 Embedding SDK；严格模式缺失即失败（H-03）。
4. PIXIU 作为原创 MemoryProvider/适配层接入可用的 openKylin Agent 宿主，完成
   多会话、多轮、规划、工具自主选择、Shell、联网搜索、审批、流式状态与停止恢复。
5. 对话、工具结果、行为和手动配置进入统一记忆管线；记忆可自主召回、价值判断、
   回写、跨会话复用并可精准遗忘。
6. 至少三台设备通过离线写入、并发更新、重连反熵、冲突仲裁、共享遗忘与最终收敛。
7. 单个版本化 `.deb` 可由 V11 图形安装器一键安装；软件 GUI 可完成检查更新、
   独立签名校验、授权升级、迁移、健康检查和失败恢复，且用户数据不丢失。
8. `AcceptanceTestSpecification.md` 中 H、A、F、P、R 项均有同一候选 commit 的
   可复现证据；D-01～D-10 均已生成规定格式并经人工审核。
9. 源码、依赖、许可证、SBOM、包、报告、PPT、视频和证据 manifest 的版本与摘要一致。

## 2. 执行原则

- **实现路线**：执行 ADR-0001；不从零重造 OS Agent，以固定版本的
  `kylin-agent`/`agent-runtime` 为宿主，PIXIU 保持作品主体和记忆创新边界。
- **模块边界**：A 仅改 `frontend/`；B 仅改 `backend/engine/` 与必要的 core 公共
  契约；C 仅改 `backend/foundation/`；E 仅改 `integrations/kylin_agent/`；跨模块
  装配只在公开 API、core 契约和 DI 组合根发生。
- **测试先行**：每个行为先提交失败测试或在同一小提交中留下清晰红绿证据；先跑
  单测，再跑模块测试，阶段末跑全量回归。
- **证据分层**：portable/Debian、模拟 SDK、V11 真 SDK、单机与多机证据分开保存，
  不以兼容路径冒充赛事门槛。
- **密集同步**：一个可审查逻辑切片一个本地 commit；每次提交后立即推送当前远程
  `main`。不做 force push，不在门禁通过前创建“最终版”标签。
- **文档伴随代码**：每个代码提交同步更新受影响模块架构、任务、API、配置、部署、
  测试报告和本计划状态；官方两份原件始终保持哈希不变。

1. 冻结候选 commit，生成源码包、`.deb`、SBOM、D-01～D-10 和原始证据。

4. 生成只读 manifest：文件名、版本、大小、SHA-256、独立签名、生成命令和 commit。
5. 两名团队成员分别执行技术审查与材料审查；负责人签字后方可创建最终标签和 Release。
6. 对已发布资产再次做下载、签名、图形安装和 GUI 升级验收，再提交赛事平台。
